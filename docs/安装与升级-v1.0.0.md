# RDC 远程桌面 v1.0.0 安装与升级

本文对应 `1.0.0`。命令与路径均为默认值；用户可在安装向导或解压时改选位置。所有校验值以 `docs/发布物清单-v1.0.0.md` 为准。

## 1. Windows：安装包与便携包

### 1.1 两者的区别

| 项目 | 安装包 `rdc-desktop-1.0.0-windows-x64-setup.exe` | 便携包 `rdc-desktop-1.0.0-windows-x64-portable.zip` |
| --- | --- | --- |
| 默认位置 | `%LOCALAPPDATA%\Programs\RDC 远程桌面` | 解压后的 `RDC 远程桌面` 文件夹，位置自选 |
| 数据位置 | `%LOCALAPPDATA%\RDC`（账号库、日志、崩溃日志） | 包内 `data\`（`config.json`、`accounts.db`、`logs\`） |
| 注册表 | 写 HKCU 卸载键，不写 HKLM | 不写注册表 |
| 快捷方式 | 桌面 + 开始菜单 | 无，双击目录内 `rdc-desktop.exe` |
| 管理员权限 | 不需要（`RequestExecutionLevel user`，不弹 UAC） | 不需要 |
| 卸载 | 运行 `Uninstall.exe` 或「应用和功能」 | 删除整个文件夹 |
| 账号库隔离 | 独立 | 独立，不与安装版共用 |
| 适用场景 | 长期使用、需要快捷方式与卸载入口 | 免安装、放在 U 盘或受控目录、快速替换 |

两个包默认目录同名（`RDC 远程桌面`）。直接解压到安装版同一父目录会触发合并/覆盖；要并列使用，把便携目录改名，例如 `RDC 远程桌面-portable`，或解压到另一个父目录。

### 1.2 安装包使用步骤

1. 校验安装包：

```powershell
Get-FileHash -Algorithm SHA256 .\rdc-desktop-1.0.0-windows-x64-setup.exe
```

与发布物清单中的 SHA-256 逐字比对，不一致不要运行。

2. 双击 `rdc-desktop-1.0.0-windows-x64-setup.exe`，按向导选择目录（默认当前用户目录）。
3. 安装完成后从桌面或开始菜单启动「RDC 远程桌面」；首次启动会在 `%LOCALAPPDATA%\RDC` 生成 `accounts.db`、`config.json` 与 `logs\`。
4. 升级：退出正在运行的客户端，直接运行新版本安装包覆盖安装。账号库与日志保留。
5. 回滚：卸载 1.0.0 后安装旧版安装包；`%LOCALAPPDATA%\RDC` 不会被卸载器删除，账号保留。
6. 卸载：运行安装目录下 `Uninstall.exe`，或「设置 → 应用 → 已安装的应用」卸载。卸载会删除安装目录、HKCU 卸载键与快捷方式，保留 `%LOCALAPPDATA%\RDC`；要彻底清除需手动删除该目录。

### 1.3 便携包使用步骤

1. 校验 zip：

```powershell
Get-FileHash -Algorithm SHA256 .\rdc-desktop-1.0.0-windows-x64-portable.zip
```

2. 右键「全部解压缩」，得到唯一的顶层文件夹 `RDC 远程桌面`，不要散落到当前目录。
3. 双击其中的 `rdc-desktop.exe` 启动，不会出现控制台黑窗。
4. 升级：退出客户端，解压新包到新目录；需要沿用账号与配置时，把旧包 `data\` 复制到新包同名位置，再启动。
5. 卸载 / 回滚：直接删除整个文件夹；回滚即换回旧文件夹。

## 2. Linux 安装

支持 Ubuntu 22.04 及同代 X11 桌面。Wayland 不支持。产物分 `linux-x64` 与 `linux-arm64`，按机器架构选择。

### 2.1 deb 安装

```bash
sha256sum rdc-desktop-1.0.0-linux-x64.deb
sudo dpkg -i rdc-desktop-1.0.0-linux-x64.deb
```

安装位置与注册项：

| 项目 | 路径 |
| --- | --- |
| 程序本体 | `/opt/rdc-desktop/` |
| 命令入口 | `/usr/bin/rdc-desktop` |
| 应用菜单项 | `/usr/share/applications/rdc-desktop.desktop` |
| 图标 | `/usr/share/icons/hicolor/{16,24,32,48,64,128,256}x*/apps/rdc-desktop.png` |
| 账号库与日志 | `~/.local/share/rdc/` |

启动：应用菜单搜「RDC 远程桌面」，或终端执行 `rdc-desktop`。

升级：`sudo dpkg -i` 新版本 deb，用户数据保留。卸载：`sudo dpkg -P rdc-desktop`，用户数据 `~/.local/share/rdc` 保留，需手动删除才能彻底清除。

### 2.2 便携 tar.gz

```bash
sha256sum rdc-desktop-1.0.0-linux-x64-portable.tar.gz
tar -xzf rdc-desktop-1.0.0-linux-x64-portable.tar.gz
cd rdc-desktop-1.0.0-linux-x64
./rdc-desktop
```

- 包内含 `portable.marker`，配置、账号库、日志写入包内 `data/`，不碰 `~/.local/share/rdc`。
- 依赖系统 Qt/X11 运行库；最小化系统需先安装 `libxcb-cursor0 libxkbcommon-x11-0 libgl1` 等。
- 升级：解压新目录，需要沿用数据时复制旧包 `data/`；删除目录即卸载。

### 2.3 Linux 被控端（X11）

被控端由 `src/rdc/` 的平台端口提供，脚本入口为 `scripts/start-host.sh`。仅 X11，需在桌面会话内启动；设备 ID 与连接码每次启动重新生成，不写入仓库与证据。运行环境需具备 Python 的 `av`（H.264 编码）与 `numpy`（像素处理）；二者为延迟导入，缺失时被控端会返回「缺少 H.264 编码依赖 av / 缺少像素处理依赖 numpy」。详见 `docs/使用说明-反向控制.md`。

### 2.4 备用监听端口（443，可选）

用途：家庭或公司上游设备（光猫、路由器、公司网关）只允许标准端口 80 / 443 入站、不提供自定义端口映射时，被控端除主端口 27888 外**默认额外监听 443**（`HostConfig.extra_ports` 默认 `(443,)`），与主端口共用同一套首帧分流与直连接管逻辑。置空 `extra_ports` 即关闭。

使用前提与行为：

1. 需自行腾出本机 443。若本机已有服务占用 443（例如本机反向代理、FastGithub 等），备用监听绑定会失败。
2. 绑定失败只记日志并降级跳过，**不影响 27888 的正常监听与连接**，被控端照常可用。
3. 该端口按设计允许公网来源进入认证流程（`HostConfig.open_ports` 语义），但**设备 ID 校验、连接码校验与会话准入门槛不降**：来源放开只放宽网络白名单，不减少任何认证步骤。
4. 安全提示：启用后 443 对公网开放，务必使用足够强度与长度的连接码（不要使用连续数字、生日等弱码），避免被在线尝试；长期不需要公网直连时可关闭备用端口，仅保留 27888。

实测说明：本版蜂窝场景的 IPv6 直连 / 打洞未通过验证（家庭上游只允许 80 / 443 入站，改用 443 备用监听仍未打通），因此该端口目前只作为具备标准端口放行条件时的尝试项，不构成蜂窝直连能力的承诺，详见 `docs/发行说明-v1.0.0.md` 4.2 第 4 条。

## 3. Android 侧载安装

包名 `com.rdc.remote`，仅 `arm64-v8a`，minSdk 29（Android 9 及以上），仅控制端，不上架应用商店。

1. 校验 APK：

```powershell
Get-FileHash -Algorithm SHA256 .\rdc-control-1.0.0-arm64-v8a-release.apk
```

2. 手机开启「允许安装未知来源应用」或「通过 USB 安装」。
3. 方式一（推荐，adb）：

```powershell
adb devices
adb install -r .\rdc-control-1.0.0-arm64-v8a-release.apk
adb shell dumpsys package com.rdc.remote | Select-String 'versionName|versionCode'
```

期望 `versionName=1.0.0`、`versionCode=10`。方式二：把 APK 传到手机，用文件管理器点击安装。

4. 升级：必须使用同一签名密钥，且 `versionCode` 递增；`adb install -r` 覆盖安装即可。签名不一致会报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，只能卸载重装。
5. 回滚：Android 不允许降级安装。需要回退时先卸载 1.0.0，再装旧包；本地账号与登录态会丢失，操作前先导出诊断。
6. 常见失败：`INSTALL_FAILED_NO_MATCHING_ABIS` 表示手机不是 arm64；`INSTALL_PARSE_FAILED_NO_CERTIFICATES` 表示 APK 损坏或校验值不符。

v1.0.0 不列入 macOS 发行物，也不提供 macOS 安装包或便携包。v1 不做 Apple 签名与公证，不接触 Apple 开发者账号、不产生任何付费；macOS 支持在后续版本补齐。macOS 用户请勿使用 Windows / Linux 包尝试运行。

## 5. 客户端自更新

### 5.1 更新源（切换源不改代码）

优先级：环境变量 > `config.json` > 默认值。

| 形态 | 配置示例 | 清单地址 |
| --- | --- | --- |
| GitHub（默认） | `github:itwuge/RemoteDesktop` | `https://github.com/itwuge/RemoteDesktop/releases/latest/download/update-manifest.json` |
| GitHub 固定 tag | `github:itwuge/RemoteDesktop@v1.0.0` | `https://github.com/itwuge/RemoteDesktop/releases/download/v1.0.0/update-manifest.json` |
| 自建镜像 | `mirror:https://mirror.example.com/rdc/latest` | `<base>/update-manifest.json` |
| 本地目录 | `local:D:\RDC-Build\release-sim\v1.0.0` | `<dir>/update-manifest.json` |

环境变量：

- `RDC_UPDATE_SOURCE`：完整更新源字符串，优先级最高，例如 `mirror:https://mirror.example.com/rdc/latest`。
- `RDC_UPDATE_REPO`：只指定 GitHub 仓库，等价于 `github:<repo>`。
- `RDC_UPDATE_MANIFEST`：清单资产名，默认 `update-manifest.json`。

`config.json` 与程序同级（便携版在 `data\config.json`，安装版在 `%LOCALAPPDATA%\RDC\config.json`）：

```json
{
  "update_source": "github:itwuge/RemoteDesktop"
}
```

切换 GitHub、镜像、本地目录只改这一处配置或环境变量，不改代码、不重新打包。

### 5.2 安全约束

1. 更新清单必须带 Ed25519 签名；缺签名、算法不符、内置公钥不匹配、内容或签名被篡改均返回 `UPDATE_SIGNATURE_INVALID`，不进入下载。
2. 下载完成后流式计算 SHA-256；不匹配删除文件并返回 `UPDATE_HASH_MISMATCH`，不执行、不提示安装。
3. 清单版本不高于当前版本时返回 `UPDATE_DOWNGRADE_REJECTED`，不接受降级安装。
4. 未先检查更新就下载会被拒绝。
5. 非回环 `http://` 更新源与资产地址一律拒绝，返回 `UPDATE_SOURCE_INSECURE`；只允许 `https`、`file`、`local:` 与相对路径。
6. 启动静默检查失败只写日志，不阻塞启动、不弹错误框。
7. 当前版本只下载与校验，不自动执行安装包；安装由用户确认后进行。

### 5.3 使用步骤

1. 打开「设置 → 诊断」确认「更新源」显示符合预期。
2. 点击「检查更新」。有新版本时更新面板显示最新版本、说明、是否强制与最低可运行版本。
3. 点击下载，等待进度与校验结果；校验通过后按提示运行安装包。
4. 校验失败时面板显示中文原因，下载文件已清理，可重试或联系维护者核对发布物清单。

### 5.4 本地演练命令（只生成本地命令，不推送、不建 tag、不写令牌）

```powershell
$env:PYTHONPATH = "src;scripts;D:\RDC-Build\tools\pylibs"
$env:RDC_BUILD_ROOT = "D:\RDC-Build"

# 1) 构建 Windows 两套包（产物落 D:\RDC-Build\artifacts\desktop）
python scripts\build_windows.py
python scripts\build_installer.py

# 2) 生成并签名本地更新清单（私钥只在本机 D:\RDC-Build\keys\，不回显、不入库）
python scripts\make_update_source.py --build-root D:\RDC-Build

# 3) 启动本地 HTTP 源（仅本机回环联调）
python -m http.server 8800 --directory D:\RDC-Build

# 4) 客户端把更新源切到本机镜像（示例；也可用 local: 目录源）
#    $env:RDC_UPDATE_SOURCE = "mirror:http://127.0.0.1:8800/update-source"
```

发布演练脚本 `scripts/publish_release.py` 只生成清单与 `release-sim` 目录，并打印 `git tag` / `gh release create` 命令，**不执行**、不上传、不读取令牌。完整命令见 `docs/发布物清单-v1.0.0.md` 第 4 节。
