### 桌面端安装与启动（用户入口）

| 项目 | 内容 |

双击入口 `启动桌面端.vbs` 不创建控制台窗口：若同目录存在打包产物 `rdc-desktop.exe` 就直接启动它，否则用 venv 的 `pythonw.exe -m rdc.ui`；启动脚本仍会完成三步：建立 venv → 按锁定版本安装依赖 → 交给无控制台入口拉起界面。重复双击幂等，依赖已就绪时直接启动。命令行等价方式：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start_desktop.ps1            # 安装检查并启动
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start_desktop.ps1 -NoStart  # 只做安装检查
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start_desktop.ps1 -Reinstall # 重建虚拟环境
```

实测结果：主窗口标题 `RDC 远程桌面 · V1`，进程响应正常，无 stderr 输出；7 页逐页切换无异常，未登录时命令返回区显示 `请先登录账号 [CREDENTIAL_INVALID]`，各页均为明确的未连接 / 未登录空状态。窗口与逐页截图存于 `evidence\ui-snapshots\20261110-0947\`。

注：`启动桌面端.vbs` 由 Windows Script Host 直接执行，不经过 cmd.exe，因此双击不会出现黑色控制台窗口；脚本内容为 ASCII，避免不同代码页下解析异常。运行日志统一写入 `logs\rdc.log`，未捕获异常写入 `logs\crash.log` 并弹出可见提示，详见 `docs\无控制台启动与崩溃排查.md`。

命令层、协议层、界面层在 `src/rdc/`，单测在 `tests/`，约定 Python 3.12。在项目根执行：

桌面界面为 PySide6 单套代码三平台，共 7 页：首页/连接、设备列表、屏幕墙（1/4/9/16 宫格与预览格升级）、会话窗（远端画面容器、状态条、工具栏、文件传输面板、剪贴板开关、拖拽落点）、设置、登录/注册、申请与审批。界面层只收集参数并调用 `rdc.commands`，会话、传输、加密逻辑不在界面内；无后端时显示「未连接 / 请先登录账号」，各页可构造、可切换、不崩溃（离屏冒烟覆盖）。

## 六、当前环境限制

1. 本机只有一台 Windows 11，没有 Ubuntu 22.04 控制端。P0-02 暂以单机双角色与 UDP 回环验证信令、握手与密文收发，跨机链路待 Linux 端就位后补测，补测通过前 P0-02 只记为功能冒烟通过。
2. Hyper-V / WSL2 过渡控制端不可用（2026-11-10 实测）：当前进程非管理员；`HypervisorPresent=False`；`hvhost` 服务 Stopped；`wsl -l -v` 报未安装 Linux 子系统。CPU 虚拟化已在固件开启且支持 SLAT，但启用 Hyper-V 或 WSL2 需要管理员权限并重启，超出本会话范围。P0-04 未执行，停在文档层，证据见 `%RDC_BUILD_ROOT%\evidence\poc\csv\p0-04_readiness.json`。
   补充（同日探测）：本机已装 VMware Workstation Pro 17.6.3，已有 Ubuntu 22.04 虚机在跑（NAT VMnet8，192.168.37.132），但 guest 无账号口令、22 端口不通，控制端验证仍未执行；该虚机只作开发与功能验证，**不是部署拓扑的一部分**。
3. 本机无硬件 H.264 编码器：GT 710 无 NVENC，X99 平台无核显，无 AMD 显卡。按 PoC 计划风险 1 走软件编码（libx264 ultrafast），指标按软件口径记录，硬件编码路径留到第 1 批。libx264 属 GPL，只用于 PoC，发布构建禁用。
4. 4K60 只能用软件编码做上限测试（显示器仅 1920×1080，无法真实采集 4K）：P0-03b 实测 3840×2160、20 秒、533 帧，可达 26.64fps，编码 p50 35.437ms、p95 42.721ms，进程 CPU 4.22 核，RSS 峰值 519.2 MiB，码率 3291.5kbps。结论：**软编不能承载 4K60，也不能稳定承载 4K30**；属「软编口径，硬编待复测」，不得当作 4K60 端到端通过。
5. 手机 240fps 慢动作替代口径不可得：本机只检测到 DR-MX200C 摄像头（状态 Unknown），无 240fps 采集设备，端到端延迟取证仍空缺，待摄像机或手机到位后补测。
6. 自签证书与测试密钥只放 `D:\RDC-Build\temp\`，不进仓库、不进日志、不进发布产物，由 S01 复核。

## 七、信令与中继服务部署（真实 ECS）

部署目标是现有阿里云 ECS（Ubuntu 20.04 x86_64），**不用本机虚拟机当服务器**。部署物在 `deploy/relay/`，完整说明与上线输入项见 `deploy/relay/README.md`。

```powershell
# 本地离线校验（不写任何文件）
python deploy\relay\deploy.py --dry-run --config deploy\relay\relay.conf.example
$env:PYTHONPATH = 'src'
python -m rdc.relay --check-config --config deploy\relay\relay.conf.example
python -m pytest tests\test_relay_server.py tests\test_relay_dataplane.py tests\test_relay_tls.py -q
$env:RDC_BUILD_ROOT = 'D:\RDC-Build'
python -m poc.tools.run_relay_dataplane_check
python -m poc.tools.run_relay_tls_check
```

```bash
# ECS 上从零部署；重复执行为幂等
sudo python3 deploy.py --config relay.conf.example
```

上线默认值（已先定，等用户改）：主机 `<ECS-IP>`、对外端点 `relay://<RELAY-DOMAIN>:<RELAY-PORT>`、出口 3 Mbps、最大并发 2 路（3 Mbps 分 4 路每路约 690 kbps，画质会低于 360p）、SSH 保持 22 不动。按此配置单会话预算 1380 kbps。真实地址与端口只在本地运维副本中维护，不入库。

当前状态：语法检查、离线 dry-run、配置校验、152 项单测（含数据面与 TLS）已通过；双进程回环验证了**密文逐字节转发**与**预算限速丢帧**，证据在 `%RDC_BUILD_ROOT%\evidence\poc\relay\dataplane-check.json`。TLS 1.3 已在本地回环完成四场景等价验证（单向、双向无证书被拒、双向正确证书通过、错误 CA 被拒），证据在 `%RDC_BUILD_ROOT%\evidence\poc\relay\tls-check.json`；自签证书生成与单向/双向取舍见 `deploy/relay/README.md` 第六节。**ECS 上的实际部署与 systemd 启动未执行**（缺登录方式）；数据面未跨公网，不是画质通道验收。
