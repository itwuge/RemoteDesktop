## 版本口径

`docs/design/ui-v2/` 冻结后只允许图标级、文案级修订，在本文件登记修订号，不新开目录。涉及页面结构、交互流程、命令入口或布局骨架变化时，必须新建 `docs/design/ui-v3/`，并把 `ui-v2` 置为只读历史版本；新目录仍须自带原型、说明、令牌、与上一版的功能对照表。

## r6 说明（现行）

- 冲突裁定顺序（用户 2026-11-11 拍板）：`design-tokens.json` → `界面说明.md` → `桌面原型.html`；实现与文档冲突一律改实现；C 类契约缺口只登记不改契约正文。
- **① 插画几何**：原型 `auth-art` 圆形加号写作 `M180 34v12`、`M174 40h12`，圆心为 `(180,46)`，加号中心落在 `(180,40)`，明显偏离圆心。按令牌与视觉基准取「加号居中」，实现竖线 `(180,35)-(180,57)`、横线 `(169,46)-(191,46)`；显示器、手机、虚线连接线坐标与原型一致。
- **② 演示外壳**：原型顶部命令标签（`login_account()` 等）、状态切换器与 40px 自绘标题栏按 r4 属演示外壳，不进实现；实现保持界面零英文。
- **③ 刷新入口**：`界面说明.md` §5「账号页」命令清单含 `accounts.refresh_session_token`，原型登录页只有一行提示、无刷新按钮。按优先级取说明的「可消费」口径、取原型的「无按钮」版式：本版不设可见刷新按钮，命令调用保留在命令层，令牌过期由登录态恢复路径处理。
- **④ 约束文案**：原型 placeholder 为「邮箱或账号名」「请输入口令」「再次输入口令」；真实约束以标签右侧 10px 附注呈现——账号「3 至 64 位」、口令「至少 8 位」。命令层 `ACCOUNT_NAME_PATTERN` 实为 3 至 64 位，此前界面写的「3 至 32 位」属实现文案错误，本版按命令层更正。
- **⑤ 令牌掩码**：`get_account_state()` 白名单（契约-202611-018 §6.2.2）不含任何令牌，界面无法取得掩码原文。故「设备令牌」只以一行附注显示「未签发 / 已签发」，不显示首尾 4 位、不提供复制；如需掩码展示，按 C 类登记，由命令层补字段后再上屏。
- 导航分组差异（原型「工作台 / 空间 / 账号与系统」vs 实现分组）属全局外壳，用户明确本版不改，只在判定表登记。

## r4 说明（现行）

- **口径覆盖**：用户 2026-11-11 明确指示「B 类原型修订在 ui-v2 内改、记 r 修订号」，故本轮页面结构级补项仍记 r4，不新开 `ui-v3`；此前「结构变化必须升 ui-v3」的口径被本条指示覆盖，仅对 r4 生效，后续结构变化仍按版本口径执行。
- 首页「被控中」：新增状态视图，含本机设备编号（含复制）、6 位接入码、有效期、被控状态、刷新接入码/停止被控；对应实机首页被控态，双方现已同态。
- 演示外壳：标题栏可见标注「演示外壳 · 不进实现」，覆盖 40px 自绘标题栏、窗口按钮、命令标签、状态切换器和演示数值。
- 缺口标注：`待契约落地` 使用原型既有 `gap` 样式（虚线下划线 + 悬浮说明），分别标注 G1 连接超时、G2 剪贴板同步默认、G3 消息导出、G4 中继可用性，明细见 `evidence/ui/align-20261111-uiv2/契约缺口单.md`。

## r3 图形说明（现行）

- 形态：显示器轮廓（圆角屏幕 + 居中支架与底座），向右箭头位于屏幕内部正中，箭头长度约占屏幕内宽 2/3，箭头高度约占屏幕内高一半；箭头与屏幕均为同一线宽，避免「主体大、箭头小」。
- 校准：四格统一 `viewBox 0 0 24 24`、`stroke-width: 1.75`、圆角端点与连接、`fill: none`，页签内 `20 × 20`；「连接」与「设备」共用 18.5×11.5 屏幕与同一支架几何，设备页签使用 `#i-monitor-tab`，其他页面的 `#i-monitor` 不受影响。
- 素材来源：按用户样图自绘内联 SVG，未引入第三方素材。
- 未改：底部导航顺序、文案、选中态、会话全屏隐藏导航的行为。

## 历史说明

- r1 的「屏幕 + 外置右箭头」形态、r2 的「小箭头靠右」形态均已被 r3 取代，仅保留记录，不再用于实现。

## 图标结论（2026-11-11 定案）

- **r1–r3 的「连接」图标稿均不作为实现基准**。安卓底部导航图标以现有 app 的视觉为准，实现线不得按 r1/r2/r3 任一路径重绘。
- 原型中的 r1–r3 图形仅作设计参考保留，不删除、不把原型改回旧图标；本目录的图标清单与图形说明只描述原型现状，不代表实现要求。
- 若后续需要统一图标风格，应新建 `ui-v3` 并按该版本目录的说明与令牌执行，不在 `ui-v2` 内继续修订。
