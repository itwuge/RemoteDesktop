# 反向控制上手说明（Windows 控制 Ubuntu）

## 一句话上手

双击 `启动演示.bat`：自动启动 Ubuntu 被控端并连上，直接看到并操作远端桌面；断开后点「连接」可重连，关窗口即停掉被控端。

> 本机演示配置已放在仓库之外（`%USERPROFILE%\.rdc-demo\host.txt`），连接码每次启动现取现用，不落盘、不写进仓库与证据。

以下为不依赖一键入口的手动方式，用于排查或单独演示。

---

本文对应「Windows 当控制端、Ubuntu 虚机当被控端」这条链路。三分钟能走完：起被控端 → 填地址连接 → 验证键盘输入 → 断开。

- 控制端：Windows 宿主机，界面程序 `scripts/rdc_control_app.py`，双击根目录的 `启动控制端.bat` 即可。
- 被控端：Ubuntu 22.04 虚机（192.168.37.132），`scripts/rdc_host_linux.py`，在虚机桌面里用一条命令启动。
- 中继与信令跑在被控端进程内，端口 `27888`（健康检查 `127.0.0.1:27889`），不依赖外部服务。

## 1. 启动 Ubuntu 被控端（约 40 秒）

在 Ubuntu 虚机的桌面里打开终端，执行：

```bash
bash ~/rdc/app/scripts/start-host.sh
```

终端会出现类似下面的提示，保持这个终端窗口不要关：

```text
========================================================
启动成功: Ubuntu 被控端已就绪, 正在等待控制端连接
监听地址: 192.168.37.132:27888
设备 ID : <16 位设备 ID>
连接码  : <6 位数字>
--------------------------------------------------------
在 Windows 控制端填写以上三项, 然后点击「连接」。
停止被控端: 按 Ctrl+C
========================================================
```

设备 ID 与连接码每次启动都会重新生成，只显示在这个终端里，不会写入任何文件。

如果提示「当前没有可用的 X11 桌面」，说明脚本不是在桌面会话里执行的；请在该虚机的桌面终端里运行，而不是在无图形环境里运行。

## 2. 在 Windows 上连接（约 20 秒）

1. 双击项目根目录的 `启动控制端.bat`，出现「RDC 控制端 · 远程操作 Ubuntu」窗口。
2. 依次填写：
   - 服务器地址：`192.168.37.132`
   - 端口：`27888`
   - 设备 ID：照抄被控端终端里的那一行
   - 连接码：照抄被控端终端里的那一行
3. 点击「连接」。底部状态条会依次显示：
   - `正在连接 …` → `已连上被控端, 正在校验连接码 …` → `连接码正确, 正在建立画面通道 …`
   - `已连接 · 远端画面 1920x1080 · 可直接操作`
4. 画面出现后，在窗口里点一下，让键盘焦点落在画面上。

## 3. 验证键盘与鼠标真的生效（约 30 秒）

1. 在 Ubuntu 里打开「文本编辑器」（gedit），新建一个空白文档，用鼠标在正文区域点一下。
2. 回到 Windows 控制端窗口，在画面上点一下，然后直接敲字。
3. 画面里应同步出现你敲的字符，Ubuntu 本机的文本编辑器里也会真实出现同样的内容。
4. 鼠标单击、右键、滚轮同样会作用到 Ubuntu 桌面。

判定标准：控制端画面与 Ubuntu 本机屏幕一致，且输入的文字落在 Ubuntu 的光标位置，而不是只出现在控制端窗口里。

## 4. 断开（约 5 秒）

- 点控制端的「断开」：被控端终端打印 `[状态] 已断开: 控制端主动断开`，随后 `[状态] 等待新的连接`，可以再次连接。
- 直接关闭控制端窗口：效果同上。
- 结束被控端：在被控端终端按 `Ctrl+C`，端口关闭。

## 5. 状态与失败原因对照

| 控制端显示 | 含义与处理 |
| --- | --- |
| 正在连接 … | 已发起 TCP 连接，等待被控端应答 |
| 已连上被控端, 正在校验连接码 … | 信令已通，正在校验连接码 |
| 已连接 · 远端画面 … | 数据面已通，画面在传输 |
| 连接失败: 被控端拒绝了连接 | 被控端没启动、端口不对，或地址写错 |
| 连接失败: 连接超时 | 地址不可达（虚机没开机、网络不同） |
| 连接失败: 连接码不正确 | 连接码抄错；被控端重启后连接码会变 |
| 连接失败: 被控端已有会话正在进行 | 上一次会话没断开，先断开再连 |
| 已断开: … | 会话已结束，可重新点「连接」 |

被控端终端里对应会打印 `[状态] 控制端 … 已通过准入校验`、`[状态] 已连接: …`、`[状态] 已断开: …`。

## 6. 已知限制（本次记录的缺口，未改契约）

1. 只支持 X11 会话（该虚机已固定为 Xorg）。Wayland 下 mss 采集与 xdotool 注入都不可用。
2. 产品代码 `src/rdc` 里仍没有 Linux 屏幕采集与键鼠注入的端口实现；本次实现放在 `scripts/rdc_host_linux.py`，通过既有命令入口 `start_hosting` 取设备 ID 与连接码，未修改契约签名与正文。
3. 单会话：第二个控制端会被拒绝，需等前一个断开。
4. 设备 ID 与连接码不持久化，每次启动重新生成；没有账号体系与提醒。
5. 键盘支持可打印字符、回车/退格/方向键等功能键、`Ctrl/Shift/Alt` 组合键；不支持中文输入法与组合输入。
6. 鼠标支持移动、左中右键单击、滚轮；不支持按住拖拽与双击手势。
7. 信令为明文 TCP，数据面为 AEAD 加密；仅用于同一受信局域网，不要暴露到公网。
8. 被控端锁屏后画面会是锁屏界面，注入也会落在锁屏上，属预期行为。
