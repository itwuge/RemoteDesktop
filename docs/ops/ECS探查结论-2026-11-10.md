1. SSH 可直接用 root 口令登录 22 端口，OpenSSH 服务正常，无 drop-in 配置。
2. 主机为 Ubuntu 20.04.6 LTS / 内核 5.4.0-166 / 2 vCPU / 1890 MB 内存 / 40 GB 系统盘，磁盘剩余 27 GB，swap 4 GB 仅用 28.8 MB。

## 九、部署方案

### 9.1 需要放行的端口

| 端口 | 方向 | 用途 | 是否必需 |
|---|---|---|---|
| TCP <RELAY-PORT> | 入方向 | 信令 + 数据面（同端口，首帧区分） | **必需**，由用户在阿里云控制台安全组添加，授权对象建议先用 0.0.0.0/0，后续可收敛 |
| TCP <RELAY-HEALTH-PORT> | — | 健康检查，**只绑 127.0.0.1** | 不放行，安全组不得加规则 |
| TCP 22 | 入方向 | SSH | 保持现状，不动 |

出方向无需新增规则（现有出网已通）。主机侧 ufw/iptables 无需改动（当前全放通）。

### 9.2 需要安装的包

**0 个**。部署包只依赖 Python 标准库与系统自带命令（useradd、install、systemctl），Ubuntu 20.04 自带 Python 3.8.10 满足要求；因此不需要 apt update / apt install，避免装包升级带来的连带风险。

### 9.3 部署顺序

1. 【用户操作】阿里云控制台安全组入方向放行 TCP <RELAY-PORT>。
2. 上传 `deploy/relay/`（deploy.py、rdc-relay.service.tmpl、relay.conf.example、healthcheck.py）与 `src/rdc` 到服务器临时目录，校验 SHA-256。
3. 现状取证：`ss -lntp`、`nginx -T` 输出、`systemctl list-units` 快照存到临时目录（仅用于对比，不改动）。
4. `python3 deploy.py --dry-run --config relay.conf.example`（目标机零改动，先看动作清单）。
5. `sudo python3 deploy.py --config relay.conf.example`：建系统账号 rdc、写 /etc/rdc-relay、/opt/rdc-relay、/var/log/rdc-relay、安装并 enable --now rdc-relay.service。
6. 验证：`systemctl show rdc-relay -p ActiveState -p SubState -p NRestarts`、`ss -lntp | grep -E ':(<RELAY-PORT>|<RELAY-HEALTH-PORT>)\b'`（期望 <RELAY-PORT> 在 0.0.0.0，<RELAY-HEALTH-PORT> 在 127.0.0.1）、本机 socket 连通、`healthcheck.py` 返回 status=ok 与 budget_kbps、日志落盘与脱敏抽查。
7. 外网验证：从外部测 TCP <RELAY-PORT> 连通，再做一次真实客户端注册/认证与 offer 往返。
8. 重复执行一次 `deploy.py` 验证幂等（不重写未变文件、不重启服务）。

### 9.4 回滚方式

```bash
sudo systemctl disable --now rdc-relay
sudo rm -f /etc/systemd/system/rdc-relay.service
sudo systemctl daemon-reload
sudo rm -rf /opt/rdc-relay /var/log/rdc-relay
sudo userdel rdc            # 无家目录，不需要 -r
# 配置与证书默认保留在 /etc/rdc-relay，确认后再手工删除
# 最后在控制台撤销 TCP <RELAY-PORT> 安全组规则
```

回滚只影响本项目新增的单元、目录与账号，不触碰 sshd、nginx、uptermd、actssh、zerotier。全程不需要重启主机。

### 9.5 与现有服务的冲突点

| 冲突点 | 现状 | 处置 |
|---|---|---|
| 80 / 443 | nginx 独占，跑 <SITE-DOMAIN> 与 <SSH-DOMAIN> | 中继不经过 nginx，走 <RELAY-PORT>，无冲突；本轮不改 nginx 配置 |
| <RELAY-PORT> / <RELAY-HEALTH-PORT> | 空闲 | 直接使用 |
| <UPTERM-PORT> / <UPTERM-TLS-PORT> / <METRICS-PORT> / <BRIDGE-PORT> / <ZT-PORT> | uptermd、actssh 桥接、ZeroTier | 与中继无关，不动 |
| <RELAY-DOMAIN> | 无证书、无 server 块 | 明文 <RELAY-PORT> 不依赖证书；如启用 TLS 需另签证书（见 9.6） |
| 内存 | 2 GiB 机型，可用 1502 MB | 单元限 384M，可共存；需在上线检查单里加内存观测 |
| 安全组 | 未放行 <RELAY-PORT> | 放行是上线前置条件，且只能由用户在控制台做 |
| 出口带宽 | 实测高于基线 3 Mbps | 涉及计费，需用户确认后再调整配置 |

### 9.6 TLS 取舍（三选一，需用户定）

| 方案 | 做法 | 代价 | 客户端要求 |
|---|---|---|---|
| A. 明文 <RELAY-PORT>（部署包默认） | `tls_enabled=false` | 信令与数据面握手信息明文传输；数据面媒体仍为应用层密文转发 | 无 |
| B. 为 <RELAY-DOMAIN> 签 Let's Encrypt 证书 | 复用现有 webroot 走 HTTP-01 签发，证书交给中继读取（需把私钥改为 0640 root:rdc 或复制一份） | 会写 /etc/letsencrypt，可能触发 nginx reload；多一张证书要续期 | 客户端校验证书链，域名已解析到位 |
| C. 自签证书 + 客户端固定 CA | 按部署包第七节在 /etc/rdc-relay/tls 生成，30 天有效期 | 客户端需预置 CA，到期要重签并分发 | 需客户端信任自签 CA |

推荐顺序：先 A 完成上线与连通性验收，再按用户选择补 B（免客户端配置）或 C（不改公共 CA 信任）。本轮不执行任何 TLS 变更。

## 十、需要用户点头才能做的操作

1. **安全组放行 TCP <RELAY-PORT>（入方向）**：只能由用户在阿里云控制台操作，我无法也不应代做；不放行则外网不可达。
2. **上传部署包到服务器**（scp/sftp 写入 /root 或 /tmp 临时目录）。
3. **以 root 执行部署脚本**：会创建系统账号 `rdc`、写 `/etc/rdc-relay`、`/opt/rdc-relay`、`/var/log/rdc-relay`，安装并 `enable --now rdc-relay.service`（首次启动服务，不重启主机）。
4. **是否启用 TLS 及采用哪一方案**（A/B/C）：B 需执行 certbot 签发新证书并可能 reload nginx；C 需生成自签证书并把 CA 分发给客户端。
5. **中继参数确认**：`egress_mbps` 与 `max_sessions` 是否维持 3 Mbps / 2 路。实测公网出口高于 3 Mbps，若实例为按流量计费，调高并发会直接增加流量费用，需用户决定。
6. **（可选）是否收敛 SSH 暴露面**：当前 root 口令登录开放；如需改为密钥登录属于另一批变更，本轮不涉及。
7. **（可选）监控接入**：是否把 <RELAY-HEALTH-PORT> 的 /healthz 接到现有监控（仅走回环，不改安全组）。

以下操作明确**不在**本轮，也不在下一轮默认范围内，需单独批准：修改 sshd 配置、改 ufw/iptables、改 nginx 配置、重启主机、停机迁移、任何 apt 装包升级。
