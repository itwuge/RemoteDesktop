# RDC 远程桌面 v1.0.0 发行说明

- 版本：`1.0.0`（版本唯一来源 `src/rdc/version.py`）
- 发行日期：2026-11-10
- 适用对象：Windows / macOS / Linux 桌面端与 Android 控制端
- 安装步骤：见 `docs/安装与升级-v1.0.0.md`
- 发布物与校验值：见 `docs/发布物清单-v1.0.0.md`

## 1. 版本说明

v1.0.0 是首个正式版。桌面端为同一套 PySide6 代码，Android 为独立控制端。版本号从 `0.2.1` 直接升到 `1.0.0`，中间功能按模块归并，不保留 `0.3.x` 的桌面版本号。

Android 的 `versionName` / `versionCode` 已按发行决定改为 `1.0.0` / `10`，与桌面端版本号对齐。预冻结阶段已用本地工具链成功打出 release APK（`com.rdc.remote`，`versionCode 10`、`versionName 1.0.0`），但该包只作构建性验证，正式发行包在代码冻结后重新构建。

macOS 不列入 v1 发行物：v1 不做签名与公证，后续版本补齐；不接触 Apple 账号、不产生任何付费。

### 3.1 产品客户端互控能力（据实）

**当前状态：未支持。**

- Windows 与 macOS 客户端没有产品级被控端实现，不能被其他客户端控制。
- Android 只做控制端，不做被控端，不提供被控入口与屏幕墙。
- 目前可用的被控端只有 Linux X11；由 `src/rdc/` 的平台端口与脚本入口启动，面向局域网 / 演示链路。
- 因此「桌面客户端 A 控制桌面客户端 B」「手机控制桌面客户端」这类产品内互控，本版不能按已支持宣传。相关改动不在本版发行声明范围内，后续版本另行说明。

## 4. 已知问题

### 4.1 功能与互控

1. 产品客户端互控未支持，见 3.1。
2. 被控端仅 Linux X11；Wayland 不支持（`mss` 采集与 `xdotool` 注入在 Wayland 下不可用）。
3. Android 无被控能力；本地账号不跨设备同步，换机需重新注册。
4. 文件传输与剪贴板在经中继的信令降级通道下**未做端到端加密**，中继可见文件内容与剪贴板载荷；界面与日志已显式提示。
5. 远程输入在 Linux 被控端支持可打印字符、回车 / 退格 / 方向键与 `Ctrl/Shift/Alt` 组合键；不支持中文输入法与组合输入，鼠标不支持按住拖拽与双击手势。

### 4.2 网络与画质

1. 中继出口按 3 Mbps 配置，预算 3000 kbps、单名额。1080p30 在静态与常规滚动场景可行；整屏快速拖动等高运动场景需回落 720p30 或把目标码率压到 ≤2.6 Mbps。
2. 第二路接入直接返回「中继通道已满，请等待或改用直连」，不排队、不静默降级。
3. 对称型 NAT / CGNAT 下 P2P 打洞物理不可行，会自动回中继。
4. **蜂窝网络下 IPv6 直连 / 打洞未通过验证，本版蜂窝场景一律走中继，该项顺延下一版本。** 实测边界：家庭上游设备（光猫 / 路由器）只允许 80 / 443 入站，不提供自定义端口映射，27888 无法放行；已改用 443 备用监听再试，仍未打通。因此不承诺任何蜂窝直连能力，控制端在蜂窝网络下应预期经中继连接。
5. 4K60 仅在 P2P 档作设计目标，未完成硬编与真机端到端验证；编码回落软件 `libx264` 时不能承载 4K60，见 4.3 第 6 条。
6. 中继使用自签 CA，客户端以 `deploy/relay/ca.crt` 作为唯一信任锚；服务端证书到期前 14 天 / 7 天告警，续期使用 SIGHUP 热加载。
7. 安全交叉验证 A6（越权访问）在公网路径只有反向拒绝，缺少正向对照，尚不能据此判定修复有效；本机对照通过。
8. **控制端异常退出后，同一被控端最长约 90 秒不可连。** 控制端断电、强杀进程或断网时，被控端可能仍认为上一会话存在，新连接会返回「被控端已有会话正在进行」。该状态会在心跳与在线状态窗口（90 秒）到期后自动释放，无需重启被控端，等待后重试即可。正常断开（点断开或关窗口）不触发该等待。

### 4.3 平台与构建

1. macOS 不列入 v1 发行物：v1 不做签名与公证，后续版本补齐；未接触 Apple 账号、未产生付费。
2. Linux arm64 产物未在 arm64 真机启动验证，只校验了 deb `Architecture` 与 CI 构建成功。
3. Android 模拟器在本机不可用（arm64 纯软件崩溃，x86_64 缺硬件加速），端到端验证依赖真机 USB 调试；登录续存、MediaCodec 720p30 与部分 UI 提示仍需手机到场后验证。
4. Android 仅 `arm64-v8a`，`x86_64` 手机无法安装；仅侧载，无应用商店分发。
5. **Linux 被控端未做真机桌面实测**：采集、编码、键鼠注入只有单测覆盖（含 X11 采集与注入的单元测试、回环链路），未在真实物理机的桌面会话（分辨率切换、缩放、多屏、锁屏）上验证；目前可用的实测环境是 Ubuntu 22.04 虚拟机。
6. **本机编码回落软件 `libx264`**：`src/rdc/media/h264.py` 按平台依次探测 NVENC / QSV / AMF（Linux 另含 VAAPI），全部不可用时回落 `libx264` 并写 WARNING 日志。本机（及当前构建机）无可用硬件编码器，实际走软编，CPU 占用更高；1080p30 可用，4K60 不可用。

## 5. 升级方式

| 来源版本 | 目标 | 步骤 | 数据 |
| --- | --- | --- | --- |
| Windows 0.2.1 及更早 | 1.0.0 | 运行新安装包覆盖安装；0.2.0 及更早为 per-machine，建议先在「应用和功能」卸载旧版 | `%LOCALAPPDATA%\RDC` 账号库、日志保留 |
| Windows 便携版 | 1.0.0 | 解压新包到新目录，替换旧目录；保留旧 `data\` 即可沿用账号与配置 | 包内 `data\` |
| Linux deb | 1.0.0 | `sudo dpkg -i rdc-desktop-1.0.0-linux-x64.deb` | `~/.local/share/rdc` 保留 |
| Linux 便携版 | 1.0.0 | 解压新 tar.gz 到新目录；需要沿用数据时复制旧包 `data/` | 包内 `data/` |
| Android 0.3.x | 1.0.0 | `adb install -r` 覆盖安装，必须使用同一签名密钥且 `versionCode` 递增 | 本地账号与登录态按版本迁移规则处理 |
| 客户端自更新 | 1.0.0 | 设置页「检查更新」→ 下载 → SHA-256 与清单签名校验 → 提示安装 | 不自动执行安装包 |

升级要点：

1. 自更新只接受高于当前版本的清单；降级返回 `UPDATE_DOWNGRADE_REJECTED`，不提供「强制降级」。
2. 校验失败返回 `UPDATE_HASH_MISMATCH`，已下载文件删除，不执行、不提示安装。
3. 更新源可配置为 GitHub Releases、本地目录或自建镜像，切换只改配置，不改代码；详见安装与升级文档第 5 节。
4. 便携版与安装版不共用账号库；从便携版切到安装版需重新登录或手工迁移数据。
5. Android 降级安装会被系统拒绝；需要回退时先卸载再装旧包，账号数据会丢失，操作前先导出诊断。
