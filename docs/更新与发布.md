# 客户端自更新与发布流程

面向 V1 桌面端。更新源默认走 GitHub Releases，不依赖自建更新服务器；本地目录源保留用于离线验证与发布演练。

## 1. 版本与产物命名

- 唯一版本源：`src/rdc/version.py` 的 `__version__`，`pyproject.toml` 动态读取，不在别处写死。
- 产物基名：`rdc-desktop-<version>-<platform>`，例如 `rdc-desktop-0.2.0-windows-x64`。
- 六套包命名：

| 平台 | 安装包 | 便携包 |
|---|---|---|
| Windows | `rdc-desktop-<版本>-windows-x64-setup.exe` | `rdc-desktop-<版本>-windows-x64-portable.zip` |
| macOS | `rdc-desktop-<版本>-macos-arm64.dmg` | `rdc-desktop-<版本>-macos-arm64-portable.zip` |
| Linux | `rdc-desktop-<版本>-linux-x64.deb` | `rdc-desktop-<版本>-linux-x64-portable.tar.gz` |

发布脚本按上述后缀自动识别平台与形态，命名不一致的产物不会被收进清单。

## 2. 更新清单格式（v2）

清单本身是 Release 的一个资产，默认文件名 `update-manifest.json`（可用 `RDC_UPDATE_MANIFEST` 覆盖）。

```json
{
  "schema": 2,
  "version": "0.2.0",
  "release_date": "2026-11-10",
  "notes": ["新增客户端自更新", "校验失败拒绝安装"],
  "mandatory": false,
  "min_supported_version": "0.1.0",
  "assets": [
    {
      "platform": "windows-x64",
      "kind": "installer",
      "name": "rdc-desktop-0.2.0-windows-x64-setup.exe",
      "url": "https://github.com/itwuge/RemoteDesktop/releases/download/v0.2.0/rdc-desktop-0.2.0-windows-x64-setup.exe",
      "sha256": "52f4c1b5...",
      "size": 35519250
    }
  ]
}
```

字段约束：

- `version`、`min_supported_version` 必须是语义化版本；`release_date` 为 ISO 日期。
- `mandatory` 必须是布尔值；`notes` 为字符串或字符串数组。
- `assets[].kind` 只允许 `installer`（安装包）或 `portable`（便携包）；`platform` 支持 `windows-x64`、`macos-arm64`、`linux-x64` 等，`windows-amd64` 视为 `windows-x64` 别名。
- `assets[].url` 允许 `http`、`https`、`file` 协议或本地相对路径，其他协议直接拒绝。
- `sha256` 必须是 64 位十六进制，客户端下载后流式校验；不匹配立即删除文件并拒绝安装。
- 旧版顶层级 `download_url` + `sha256` 的 v1 清单仍可解析，便于历史演练脚本过渡。

客户端按“当前平台 + 当前形态”选择资产：安装版优先 `installer`，便携版优先 `portable`；缺少当前平台资产时检查失败，不猜测其他平台包。

## 3. 更新源配置（改配置不改代码）

优先级：环境变量 > `config.json` > 默认值。

| 形态 | 配置示例 | 清单地址 |
|---|---|---|
| GitHub（默认） | `github:itwuge/RemoteDesktop` | `https://github.com/itwuge/RemoteDesktop/releases/latest/download/update-manifest.json` |
| GitHub 固定 tag | `github:itwuge/RemoteDesktop@v0.2.0` | `https://github.com/itwuge/RemoteDesktop/releases/download/v0.2.0/update-manifest.json` |
| 自建镜像 | `mirror:https://mirror.example.com/rdc/latest` | `<base>/update-manifest.json` |
| 本地目录 | `local:D:\RDC-Build\release-sim-offline\github\itwuge\RemoteDesktop\releases\latest\download` | `<dir>/update-manifest.json` |

可用环境变量：

- `RDC_UPDATE_SOURCE`：完整更新源字符串，优先级最高。
- `RDC_UPDATE_REPO`：只指定 GitHub 仓库，等价于 `github:<repo>`。
- `RDC_UPDATE_MANIFEST`：清单资产名。

`config.json` 与打包目录同级：

```json
{
  "update_source": "github:itwuge/RemoteDesktop"
}
```

未配置时使用默认 GitHub 仓库 `itwuge/RemoteDesktop`，客户端不携带任何令牌。

## 4. 发布流程（一条命令，先本地演练）

```powershell
$env:PYTHONPATH = "src;scripts;D:\RDC-Build\tools\pylibs"
python scripts/publish_release.py --build-root D:\RDC-Build
```

脚本依次完成：

1. 校验版本号与代码一致，按命名规范归集各平台产物，同一平台同一形态重复直接失败。
2. 生成 v2 清单资产，写入 `<构建根>\release-sim\<tag>\`（待上传资产集合）。
3. 同时铺出 GitHub Release 目录结构：
   - `release-sim\github\itwuge\RemoteDesktop\releases\download\<tag>\`
   - `release-sim\github\itwuge\RemoteDesktop\releases\latest\download\`
4. 逐目录回读清单，逐个核对资产 SHA-256 与大小，写 `release-report.json`。
5. 打印 `git tag` / `gh release create` / `gh release upload` 命令，但**不执行**。

本机演练不创建仓库、不推送、不上传任何外部服务。

离线目录源演练（清单内资产用相对名）：

```powershell
python scripts/publish_release.py --relative-asset-urls --out D:\RDC-Build\release-sim-offline
```

完整端到端验证（发布演练 → 检查 → 下载 → SHA-256 校验 → 安装提示）：

```powershell
python scripts/e2e_release.py --current-version 0.1.0
```

## 5. 仓库前置动作清单

仓库 `https://github.com/itwuge/RemoteDesktop` 目前尚不存在时，由用户执行或授权后执行：

1. 创建公开空仓库 `itwuge/RemoteDesktop`，不要勾选自动生成 README、.gitignore、License，避免首推冲突。
2. 本地配置远端并推送首个提交：
   ```powershell
   git remote add origin https://github.com/itwuge/RemoteDesktop.git
   git push -u origin main
   ```
3. 构建并上传首版产物与清单（真实发布时才执行）：
   ```powershell
   python scripts/build_windows.py
   python scripts/publish_release.py
   git tag v0.2.0
   git push origin v0.2.0
   gh release create v0.2.0 D:\RDC-Build\release-sim\v0.2.0\* --repo itwuge/RemoteDesktop --title "v0.2.0"
   ```
4. 创建 Release 时必须把 `update-manifest.json` 一并作为资产上传；否则客户端 `releases/latest/download/update-manifest.json` 会 404。
5. 首次发布后用浏览器确认资产直链可匿名下载，再让客户端检查更新。

## 6. 私有仓库红线

- 公开仓库：客户端直接读取 Release 资产，不需要令牌。
- 私有仓库：GitHub 要求令牌才能读取 Release；令牌一旦随客户端分发，等于把仓库读取权限交给所有安装者，可被提取、滥用、无法单独吊销。**这是不可接受的做法，本项目不采用。**
- 需要私有分发时改用自建镜像或内网目录源，由服务端做鉴权；客户端仍只拿清单与产物，不内置任何凭据。
- 任何脚本、配置、产物、日志都不得写入令牌或凭据；发布脚本只打印命令，不读取 `GH_TOKEN`。

## 7. 安全底线

- 下载完成后必须校验清单声明的 SHA-256；不匹配删除文件、返回 `UPDATE_HASH_MISMATCH`，不执行、不提示安装。
- 更新源版本不高于当前版本时拒绝，返回 `UPDATE_DOWNGRADE_REJECTED`。
- 未先检查更新就下载会被拒绝。
- 启动静默检查失败只写日志，不阻塞启动、不弹错误框。
- 本轮只下载与校验，不自动执行安装包。
