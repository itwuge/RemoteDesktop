## 1. 新增消息类型 `video_frame`（v2）

- 方向：被控端 → 控制端，走会话数据面，整帧在 AEAD 密文内。
- 语义：与 v1 的 `{"kind":"video","data":<base64>}` 等价，只替换承载方式。
- 净荷：编码器输出的原始 H.264 字节，不做 base64、不放进 JSON。
- 顺序：`seq` 单调递增；`pts` 沿用编码器时间基；关键帧由 flags 位 0 标记。
- 上限：单帧净荷不超过 8 MiB，超过即拒绝。

### 1.1 定长头（28 字节，大端，`>2sBBIqHHII`）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 2 | magic | 固定 `b"RF"` |
| 2 | 1 | version | 固定 2；非 2 一律按未知版本拒绝 |
| 3 | 1 | flags | 位 0 关键帧；位 1 CRC32 有效；其余保留，接收端忽略 |
| 4 | 4 | seq | 无符号 32 位 |
| 8 | 8 | pts | 有符号 64 位 |
| 16 | 2 | width | 无符号 16 位 |
| 18 | 2 | height | 无符号 16 位 |
| 20 | 4 | payload_len | 无符号 32 位，必须等于实际净荷长度 |
| 24 | 4 | crc32 | 净荷 CRC32；flags 位 1 未置位时为 0 |

### 1.2 与 v1 的关系

- v1 继续可读：`decode_v1` 接受 `kind=video` 的 JSON+base64，字段映射到同一帧模型。
- v2 不使用 JSON，因此同一 AEAD 明文既可能是二进制帧也可能是 JSON 控制帧；接收端按前 2 字节是否为 `RF` 分流。
- 旧客户端不识别 v2，版本协商会降级到 v1，不向其发送二进制帧。

## 2. 版本协商

- `offer` / `answer` 的 `media_caps` 增补可选字段 `frame_versions`（整数数组，按优先级降序），例如 `[2, 1]`。
- 缺省、为空或含非法类型时视为 `[1]`；双方取最高共同版本，无共同版本时固定降级 v1。
- 本端可单方面把 `frame_versions` 收紧为 `[1]` 做灰度回退，不需要改对端。
- 滚动升级期允许收发版本不一致：协商结果决定发送版本，接收端必须同时能解 v1 与 v2。

## 3. 新增局部错误码

以下错误码只在帧编解码层使用，尚未进入契约错误码表：

| 错误码 | 触发条件 |
|---|---|
| `FRAME_TRUNCATED` | 帧头不足 28 字节，或实际净荷短于 `payload_len` |
| `FRAME_LENGTH_MISMATCH` | 实际净荷长于 `payload_len` |
| `FRAME_BAD_MAGIC` | 前 2 字节不是 `RF`，且不是合法 v1 JSON |
| `FRAME_UNSUPPORTED_VERSION` | magic 正确但 version 不是 2 |
| `FRAME_CRC_MISMATCH` | 置了 CRC 位且 CRC32 不一致 |
| `FRAME_TOO_LARGE` | `payload_len` 或实际净荷超过 8 MiB |
| `FRAME_FIELD_RANGE` | 编码端字段超出 seq/pts/width/height 的位宽 |
| `FRAME_BAD_PAYLOAD` | v1 `data` 不是字符串、base64 损坏或字段类型非法 |
| `FRAME_KIND_MISMATCH` | v1 消息 `kind` 不是 `video` |

## 4. 契约缺口（只记录，不改正文）

1. 正文第三节消息类型表没有 `video_frame`，也未定义视频帧的承载、方向与 payload 字段。
2. 正文未定义 `media_caps.frame_versions` 这类媒体能力协商字段；当前只在实现与验收脚本中约定。
3. 正文错误码表没有帧级错误码，无法区分截断、长度不符、未知版本与 CRC 不符。
4. 正文未给出视频帧大小上限、`seq` / `pts` 语义与关键帧标记方式。
5. 正文中继数据面章节只描述 JSON 编码，未说明二进制帧与 JSON 控制帧在同一 AEAD 通道内共存时的分流规则。

## 6. 未验证与风险

- Android 薄壳未适配 v2：本轮约束不改 `android/`，旧版本依赖协商降级到 v1。
- 真实公网中继未回归：本轮只在本地回环中继上对比 v1/v2，公网链路需另行复跑。
- 中继按密文字节计费：v2 减少的是被控端出口与中继出口带宽，AEAD 头开销不变。
