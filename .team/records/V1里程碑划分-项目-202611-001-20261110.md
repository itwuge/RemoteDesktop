## 一、分段结论

V1 内部拆两段里程碑，验收判据相互独立：第一段不因第二段未完成而阻塞，第二段不得回退第一段已通过项。

| 里程碑 | 名称 | 内容边界 | 对外状态 |
|---|---|---|---|
| M1 | 直连 + 四端基础可用 | P2P 直连、采集编码、会话、四端可安装可连接；账号仅保留「设备凭证 + 账号令牌」最小实现 | 可独立验收 |
| M2 | 账号 + 申请制 + 免登录 + 屏幕墙 | 账号注册登录刷新、设备绑定解绑与授权列表、申请制审批、同账号免确认、桌面屏幕墙 | 在 M1 之上增量验收 |

## 二、第一段（M1）边界与验收判据

### 2.1 范围

必须包含：

1. Windows 采集与编码（DXGI + 硬件编码优先，1080p30 软编兜底）。
2. 直连通路：候选交换、打洞、UDP 三向握手、密文收发；直连失败按 L0–L3 降级到中继。
3. 会话控制：建连任务、进度、取消、会话状态与指标、结束会话。
4. 四端可安装可连接：Windows、macOS、Linux 桌面端双向（控制与被控），Android 只做控制端。
5. 画质四档与自动降级：4K60 / 1440p60 / 1080p60 / 1080p30 地板，降级可观测。
6. **账号与设备凭证的最小实现（前置项，见第三节）**。

明确不包含（留给 M2）：账号注册登录界面全流程、多设备管理、授权列表与转授、申请制审批、免确认开关、屏幕墙。

### 2.2 验收判据（独立判定）

| 序号 | 判据 | 通过条件 | 失败条件 |
|---|---|---|---|
| M1-1 | 直连建链 | 局域网双端直连成功，建立时延 p95 ≤ 3 秒，连续 30 次采样无失败 | 任一次无法建立或 p95 > 3 秒 |
| M1-2 | 1080p30 地板实测 | 限速至 8 Mbps 以下会话不断开，档位停在 1080p30，界面显示最低档提示 | 降到 1080p30 以下或断流 |
| M1-3 | 1080p60 基线 | 局域网 1080p60 会话 5 分钟，p50 ≤ 80ms、p95 ≤ 120ms，帧率 ≥ 28fps | 任一超限 |
| M1-4 | 四端可安装 | 四端安装包可安装并启动，版本号与校验和一致；Android 为已签名侧载 APK | 任一端无法安装或启动 |
| M1-5 | 自动降级 | 注入丢包或限速后 3 秒内降一档，`quality_events` 有记录，界面显示新档位与原因 | 不降档、跳档或无记录 |
| M1-6 | 安全底线 | 口令、令牌、密钥不出现在日志与仓库；抓包无明文屏幕内容 | 出现明文或凭据泄露 |
| M1-7 | 设备凭证最小闭环 | 设备首次绑定需登录一次换取设备凭证；后续用长期设备令牌 + 短时会话令牌；令牌吊销后立即失效 | 免登录路径使用明文或固定密钥 |

判据口径：

- 4K60 硬编与 240fps 端到端取证仍为「硬件受限未验证」，替代口径必须标注，不得写成通过。
- 虚拟机、模拟器与软编数据必须标口径，不得作为真机结论。
- M1-7 是 M2 的前置：不做最小凭证闭环，M2 的免登录与授权列表必须返工。

## 三、首段必须前置的最小实现（否则第二段返工）

| 前置项 | 最小实现 | 不做会怎样 |
|---|---|---|
| 设备身份 | Ed25519 密钥对 + `device_id` 派生，首次启动生成并写入本机安全存储 | M2 绑定与授权无稳定主体，设备换 ID 后授权全部失效 |
| 设备凭证 | 首次绑定登录一次换取长期设备令牌；令牌只存摘要 | M2 免登录无信任根，只能退回每次输码 |
| 账号令牌 | 短时会话令牌（默认 15 分钟）+ 刷新；吊销/解绑/改密即时失效 | M2 的踢下线与撤销无法证明有效 |
| 审计落点 | 统一审计事件名与字段（`ts`、`event`、`actor`、`target`、`result`、`detail`） | M2 审批与撤销无留痕，T01 无法取证 |
| 判定钩子 | 连接入口预留 `resolve_access` 判定点，M1 固定走临时码路径 | M2 需改动连接主流程，回归面扩大 |

## 四、第二段（M2）边界与验收判据

范围：账号注册/登录/刷新、设备绑定与解绑、授权列表（对象、范围、有效期、可否转授）、撤销即时生效；申请制（申请 → 审批 → 限时/一次性授权，拒绝留痕）；同账号免确认与开关可审计；桌面屏幕墙 1/4/9/16 宫格、预览流、点选升级、预算与降级。

| 序号 | 判据 | 通过条件 |
|---|---|---|
| M2-1 | 账号模式 | 注册、登录、刷新可用；一账号多设备；多账号经授权控制同一设备 |
| M2-2 | 撤销即时生效 | 解绑、撤销授权、改密后旧令牌立即失效，在线会话被踢并留痕 |
| M2-3 | 申请制 | 申请 → 审批 → 限时/一次性授权全流程可跑；拒绝留痕；审批与撤销可审计 |
| M2-4 | 免确认 | 同账号且 `require_confirm=false` 免码免确认直连；关闭后回到申请制；开关变更进审计；加密与鉴权不降级 |
| M2-5 | 屏幕墙 | 1/4/9/16 布局可用；预览档独立；点选升级；预算与降级顺序符合契约 v1.3 |
| M2-6 | 硬约束 | 任何时刻 4K60 解码路数 ≤ 1；禁止 N 路 4K60 同时解码，违反被命令层拒绝 |
| M2-7 | 越权复核 | S01 对四条越权路径给出结论，无未修复高危项 |

## 五、工作量与关键路径重估

| 项 | M1 原估 | 新增影响 | 调整后 | 关键路径 |
|---|---|---|---|---|
| 采集编码 | 2 周 | 无 | 不变 | 是 |
| 直连与中继 | 2 周 | 无 | 不变 | 是 |
| 会话与四端壳 | 3 周 | Android 改只做控制端，删除采集路径，减 0.5 周；新增旋转与坐标映射 0.5 周 | 3 周 | 是 |
| 账号与凭证最小实现 | 0 | 新增前置 1 周（设备身份、设备令牌、会话令牌、审计字段） | 1 周 | **是（M1 新增关键路径）** |
| 第二段账号全量 | 3 周 | 无 | 3 周 | M2 |
| 申请制与免确认 | 2 周 | 依赖 M1 凭证，可并行设计 | 2 周 | M2 |
| 屏幕墙 | 2 周 | 依赖会话与解码预算 | 2 周 | M2 |
| 界面原型与说明 | 1 周 | 新增 4 组页面（登录、设备列表、审批、屏幕墙） | 1.5 周 | 否 |

结论：新增四项使 V1 总量增加约 6.5 周，其中 1 周进入 M1 关键路径；M1 的完成时间因此顺延约 1 周，但 M1 验收判据不因 M2 未完成而失效。

## 六、四个新增项对第一段的影响

| 新增项 | 对 M1 的影响 | 处理 |
|---|---|---|
| 账号模式 | 需要设备身份、设备令牌与会话令牌的最小实现 | 纳入 M1 前置项 M1-7 |
| 申请制 | 需要连接入口预留判定点与审计字段 | M1 只留钩子，不实现审批界面 |
| 同账号免登录 | 依赖设备凭证与令牌吊销 | M1 实现令牌签发/吊销，M2 接免确认判定 |
| 屏幕墙 | 依赖会话与解码预算，不依赖采集 | 全部放 M2，M1 不做多路解码 |
