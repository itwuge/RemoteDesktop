## 二、背景与动因

| 项目 | 填写内容 |
|---|---|
| 触发来源（对应需求条目编号或缺陷编号） | v1 发行要求：账号能力跨端可用；缺陷 ACCT-CROSS-01（账号不跨端）、ACCT-PERSIST-02（登录态不持久）、ACCT-TRUST-03（信任未接入真实连接路径）、ACCT-AUDIT-04（免授权审计不写） |

## 六、受影响的接口与数据结构

### 6.1 服务端账号中心 HTTP 接口（复用现有 TLS 监听端口，不新增监听）

公共约定：路径以 `/v1` 开头；响应包络固定 `{"code": 0 | "<错误码>", "message": "<中文>", "data": {...}}`；资源名用复数；动作一律 `POST`；所有 `POST` 必须带 `Idempotency-Key` 头（10 分钟内同键重放返回首次结果）；认证使用 `Authorization: Bearer <device_token>`。

| 序号 | 方法与路径 | 作用 | 请求字段 | 返回 data 字段 |
|---|---|---|---|---|
| 1 | POST /v1/accounts/register | 注册账号 | account、password | account_id、account_name、created_at |
| 2 | POST /v1/devices/challenges | 取设备身份挑战 | device_id、device_public_key | nonce、expires_at |
| 3 | POST /v1/accounts/login | 口令登录并绑定设备 | account、password、device_id、device_name、device_platform、device_public_key、nonce、signature | account_id、account_name、created_at、device_id、device_token、session_token、expires_at、device_expires_at、platform、trusted、trusted_at、trust_source |
| 4 | POST /v1/accounts/logout | 登出并吊销本设备令牌 | 无 | revoked_tokens、kicked_connections |
| 5 | POST /v1/tokens/revoke | 吊销指定令牌或本设备令牌 | token（可空，空表示本设备） | revoked_tokens、kicked_connections |
| 6 | GET /v1/accounts/me | 校验登录态并返回账号信息 | 无 | account_id、account_name、created_at、device_id、platform、trusted、trusted_at、trust_source、expires_at |
| 7 | GET /v1/devices | 账号下全部设备与在线状态 | 无 | items[]（见 6.2） |
| 8 | POST /v1/devices/{device_id}/trust | 设置/撤销设备受信 | trusted | items[]（单个设备，见 6.2） |
| 9 | GET /v1/trusted-devices | 受信设备列表 | 无 | items[]（见 6.2） |
| 10 | GET /v1/audits?device_id=&since= | 审计事件（已脱敏） | 查询参数 | items[]（event、actor、target、result、detail、created_at） |
| 11 | POST /v1/tokens/refresh | 用长期设备令牌换短时会话令牌 | 无 | session_token、expires_at |
| 12 | POST /v1/access/resolve | 连接准入判定（供互控线接入） | device_id、scope、existing_session、session_id、dry_run（可选，预检不写审计） | route、reason、trusted、online、last_connected_at、audited |
| 13 | GET /v1/messages?device_id=&limit= | 账号消息列表（A4，安卓与桌面共用） | 查询参数 device_id（可空）、limit（默认 200） | items[]、unread、total、read_until |
| 14 | POST /v1/messages/read | 全部标记已读，推进账号级水位（A4） | 无 | read_until、cleared |

### 6.2 设备列表项字段（GET /v1/devices 与 GET /v1/trusted-devices）

`device_id`、`display_name`、`platform`（windows/linux/macos/android/unknown，未知写 unknown，不按设备名猜测）、`bound_at`、`online`（bool）、`presence_state`（online/offline/unknown）、`last_seen_at`、`require_confirm`、`trusted`（= not require_confirm）、`trust_source`（device/owner，未受信为空串）、`trusted_at`（ISO 8601，未受信为 null）、`last_connected_at`、`owner`、`current`（是否为当前调用设备）。

### 6.2.1 审计 detail 键名契约化

- `session.start` / `session.end`：`session_id`、`device_id`、`peer_device_id`、`account_id`（必有）；`transport`、`transport_kind`、`quality_profile`、`end_reason`、`reason`（有则出现）。
- `trust.change` / `trust_policy.change`：`device_id`、`trusted`、`require_confirm`、`source`、`trusted_at`。
- `access.passwordless`：`device_id`、`device_name`、`account_id`、`session_id`、`source`。
- `device.bind` / `device.bound`：`device_id`、`device_name`、`platform`。
- 上述键名由界面 `list_messages`、`mark_all_read` 直接消费；新增键必须先改本记录，不得在页面侧自造。

### 6.2.2 界面消费的命令与白名单（G6）

- `get_account_state()` 只向界面注入白名单字段：`logged_in`、`account_id`、`account_name`、`created_at`、`device_id`、`remote`、`expires_at`；**不得包含 `device_token`、`session_token` 或任何令牌**。
- `list_sessions()` / `get_session_status()` 新增 `started_at`（ISO 8601），界面据此显示已连接时长；缺失时界面保持不显示。
- `list_messages()` / `mark_all_read()` 不在 desktop-v1 第三节，已在本次变更记录登记；detail 键名按 6.2.1 契约化。

### 6.2.3 会话与连接状态字段（A8）

- `get_session_status(session_id)` 与 `get_connection_progress(task_id)` 返回 `state`，取值限定为 `connecting` / `streaming` / `reconnecting` / `recovered` / `failed`。
- `state == "failed"` 时同时返回 `reason`（中文原因，如「连接已取消」「连接失败：直连与中继均不可用」）；其他取值不返回 `reason`。
- 内部历史状态 `connected` 归一为 `streaming`，`pending` / `running` 归一为 `connecting`，`canceled` 归一为 `failed` 且 `reason` 为「连接已取消」。
- 不新增事件流、不做服务端推送；界面按现有查询命令轮询消费，取不到 `state` 时保持原展示。
- `list_sessions()` 的 `state` 与 `get_session_status()` 使用同一映射，保持口径一致。

### 6.2.4 设备在线状态轮询（A10）

- 设备在线状态定为轮询，不做推送：设备列表页可见且应用在前台时每 15 秒调用一次 `list_devices()` 刷新；退到后台或离开页面立即停止轮询。
- 在线判定仍以服务端 `presence_state`（心跳 30 秒刷新、90 秒过期）为准；界面只消费 `online` 与 `presence_state`，不在本地推断在线。
- 本线只提供数据与状态；轮询定时器与页面可见性判断由 UI 线在页面层实现。

### 6.2.5 消息项字段（A4，与服务端 /v1/messages 一致）

`message_id`、`ts`、`category`、`category_label`、`event`、`title`、`device_id`、`device_name`、`actor`、`result`、`detail`；与桌面端 `list_messages` 的 `_message` 字段完全一致。未读以服务端返回的 `unread` 为准（账号级已读水位 `read_until`），不使用本地水位计数。

### 6.3 新增错误码（仅在调用方需要分支时出现）

| 错误码 | 触发条件 | 建议处理 |
|---|---|---|
| ACCOUNT_EXISTS | 注册账号已存在 | 提示直接登录 |
| CREDENTIAL_INVALID | 账号不存在或口令错误 | 统一提示「账号或口令不正确」，不区分账号是否存在 |
| TOKEN_REVOKED | 令牌已吊销 | 清理本地登录态并要求重新登录 |
| TOKEN_EXPIRED | 令牌过期 | 清理本地登录态并要求重新登录 |
| DEVICE_BOUND_OTHER | 设备身份已绑定其他账号 | 提示设备已归属其他账号 |
| CHALLENGE_INVALID | 设备挑战不存在、过期或签名不匹配 | 重新获取挑战 |
| PERMISSION_DENIED | 目标设备不属于当前账号 | 提示无权限 |
| IDEMPOTENCY_KEY_REQUIRED | 写操作缺少幂等键 | 客户端补 `Idempotency-Key` 后重试 |

**错误码放行口径（`authorize_connection`）**：账号层把连接准入的 `denied` 结果翻译为命令结果时，`TOKEN_REVOKED`、`TOKEN_EXPIRED`、`CREDENTIAL_INVALID` 三类错误码原样返回，不再折成 `PERMISSION_DENIED`，`message` 保持与桌面端一致的中文文案；其余拒绝原因仍返回 `PERMISSION_DENIED` 并保留中文原因。界面据此区分「请重新登录」与「无权限」。该口径仅作用于 `accounts/**` 范围内，不改互控线的接入点与判定顺序。

### 6.4 客户端本地数据结构

| 序号 | 路径 | 类型 | 改动说明 |
|---|---|---|---|
| 1 | 数据目录/device_identity.json | 本地文件 | 持久化 Ed25519 设备身份私钥（0600，明文私钥仅本机用户可读），保证跨端设备标识稳定 |
| 2 | 数据目录/account_session.bin | 本地文件 | 登录态密文仓：Windows 使用 DPAPI（用户绑定），其他平台使用 AES-GCM，密钥由机器标识与用户标识派生且不落盘；内容含 account_id、account_name、account_created_at、device_id、device_token、session_token、session_expires_at、device_expires_at；退出登录即删除 |
| 3 | accounts.db（客户端本地与服务端） | SQLite | schema 升至 v6，新增可空列 `last_connected_at`、`platform`、`trusted_at`、`trust_source`，新增表 `message_reads(account_id TEXT PRIMARY KEY, read_until TEXT NOT NULL)` 保存账号级已读水位；旧库平滑迁移，既有数据不重写 |

### 6.6 UI 对齐收敛的四个命令层缺口（G1–G4）

| 缺口 | 结论 | 命令与签名 | 入参 / 出参 | 落点文件 |
|---|---|---|---|---|
| G1 设置-连接超时 | 不补 | — | — | — |
| G2 设置-剪贴板同步默认 | 补 | `save_settings(relay_endpoint, device_name, quality_profile, log_level, auto_start, clipboard_auto_sync: bool = True)` | 入参新增可选布尔；出参 `data.settings` 增加 `clipboard_auto_sync`；`get_settings()` 同步返回该键（缺省 True） | src/rdc/commands/settings.py |
| G3 消息导出 | 补 | `export_messages(path: str, limit: int = 0)` | 入参：目标文件路径（必填，非空）与条数上限（0 为全部）；出参 `data = {path, rows}`；失败 `CONFIG_INVALID`（路径为空）或 `TRANSFER_IO_ERROR`（写入失败） | src/rdc/commands/messages.py |
| G4 诊断-中继可用性/节点 | 不补 | — | — | — |

- G1 不补理由：桌面端会话建链超时由传输层按阶段固定（信令握手与数据面各自设限），`start_connection` 无超时入参，暴露为用户设置会绕过握手与吊销时序，弱网诊断也会失真。界面应把该输入项改为只读说明「连接超时由传输层按阶段自动管理」，诊断区如需自定义探测时长，用现有 `check_server(host, port, timeout_s)` 的入参。
- G2 补的理由：该值是**默认偏好**而非会话内开关，落盘后由命令层在保存成功时立即应用到剪贴板服务，页面进入会话时按 `get_settings()` 的 `clipboard_auto_sync` 初始化开关；不改 `set_clipboard_enabled` 的既有签名。
- G3 补的理由：导出属于命令层文件写入，需统一列序、UTF-8 BOM 与公式注入防护（`= + - @` 开头单元格加前导单引号），避免三端各写一套 CSV；导出只使用 `list_messages()` 已有字段，不额外推断数据。
- G4 不补理由：`get_diagnostics()` 是**离线快照**，模块约定不发起网络；中继可达性属于主动探测，已由 `check_server(...)` 提供，节点信息即 `get_diagnostics()` 已返回的 `relay_endpoint`。界面诊断区应把「可用性」呈现为一次「检测连通性」按钮的结果（显示最近一次检测），未检测时显示「未检测」，不得在快照里伪造可达性字段。
