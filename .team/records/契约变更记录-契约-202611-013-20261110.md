## 1. 新增字段：answer 的帧版本定版

`answer.media_caps` 增加整数字段 `frame_version`，值为被控端（媒体生产方）最终使用的帧版本。同时 `answer.media_caps.frame_versions` **只声明本端真正会用的版本**：

- 协商到 v2：`frame_versions = [2, 1]`、`frame_version = 2`
- 协商到 v1：`frame_versions = [1]`、`frame_version = 1`

控制端以 answer 的 `frame_version` 为准；字段缺失时退回按 `frame_versions` 交集规则计算（兼容旧被控端）。

## 2. 默认协商策略（实现约定，不入契约表）

- 本端能力固定为 `[2, 1]`，优先级从高到低；命令层单一出处 `src/rdc/commands/media_caps.py`。
- 协商结果 v1 时必须写结构化日志 `rdc.media.caps / frame_version.degraded`（WARNING），字段含 `role`、`reason`、`peer_frame_versions`；host 同时在终端提示“帧封装回退 v1, 带宽开销会上升”。
- 产品路径不得硬编码帧版本，也不得在协商失败时静默按 v1 发送而不留痕。

## 3. 数据面控制探测（验收装置内部约定，不进入契约）

- 明文分流：前 2 字节 `RF` 为 v2 帧，否则为 UTF-8 JSON 控制帧；该规则与契约-202611-011 一致，此处重申。
- ping/pong 结构收敛为 `{"kind":"ping","seq":n}` / `{"kind":"pong","seq":n}`，时间戳由发送端本地计时，不写入消息。
- 探测间隔自适应：媒体帧在流时 0.5 秒，1 秒内无媒体时 1.0 秒；数据面不另设心跳，探测即保活。
- 该约定只约束仓库内验收装置 `scripts/relay_public_bench.py`；产品数据面当前不存在 ping/pong，信令 heartbeat 维持 10 秒。

## 4. 契约缺口（继续登记，未在正文补充）

1. 正文无 `video_frame` 消息条目（沿用 011 的缺口 1）。
2. 正文未定义 `media_caps.frame_versions` 与 `frame_version` 的优先级关系（本轮明确：answer 的 `frame_version` 优先）。
3. 正文未定义数据面二进制与 JSON 共存时的分流规则（沿用 011 的缺口 5）。
4. 正文无帧级错误码表（沿用 011 的缺口 3）。
5. `src/rdc/connect/relay.py` 的 `media_caps` 仍硬编码 `{"video":["1080p30"],"audio":["opus"]}`，未带帧版本；属禁改范围，帧版本以 offer/answer 为准，待连接线统一。
