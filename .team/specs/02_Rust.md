# 02 Rust 细则

## 1. 文件名头要求

- 每个 `.rs` 文件首部用 `//!` 模块文档注释, 首行写一句模块定位, 空一行后逐行写八栏。
- 八栏栏目名与顺序同总则, 形式固定为 `//! 文件: name.rs`。
- `lib.rs`、`main.rs`、`mod.rs` 同样必须写, 不得以「入口文件」为由省略。
- crate 根文件除八栏外必须写 crate 级 lint 说明: 列出启用的 lint 与理由, 例如 `#![deny(missing_docs)]` 表示公开项缺文档即编译失败; 未启用任何 lint 时须写明原因。
- 禁止在文件头写作者、日期、变更日志、版本号。

## 2. 依赖引入区要求

- 分组顺序: `std` / 外部 crate / `crate` 内部, 组间空一行。
- 每行 `use` 行尾用 `//` 注明来源与用途: 来源为标准库路径或 crate 名, 用途为该符号支撑的功能。
- 禁止通配引入 `use foo::*`; 确需时在该行注明原因与影响范围。
- 禁止引入后未使用; 禁止同一符号用多条路径重复引入。
- feature 条件引入须写 `#[cfg(feature = "...")]`, 并在上一行用 `//` 注明该 feature 的作用与关闭后的退化行为。
- `extern crate` 仅在特定 edition 或特殊场景使用, 使用时必须写明原因。

## 3. 类型与函数注释要求

- 公开项一律用 `///` 文档注释; 私有项含副作用或超过 10 行也必须写。
- 固定小节顺序:
  1. 首行一句话定位。
  2. `# Arguments`: 逐参数写 `- *name* - 含义与取值约束`。
  3. `# Returns`: 返回值含义, 可为空或使用哨兵值时写明。
  4. `# Errors`: 何种情况下返回什么错误, 与错误类型一一对应。
  5. `# Panics`: 何种输入或状态会 panic; 不会 panic 也要写该小节并注明「不会 panic」。
  6. `# Safety`: 仅 `unsafe fn` 或含 `unsafe` 块的函数必须写, 说明调用方必须满足的前置条件; 缺 `# Safety` 的 unsafe 一律不合格。
- 类型注释写在 `struct` / `enum` / `trait` / `type` 之上; 字段用 `///` 逐字段注释, 枚举变体逐条注释。
- 含公开方法的类型在类型注释中写「方法一览」, 形式为每行 `///   pick(name, response, default) -> Option<T>: 一句话用途`, 只作速查, 真正的参数与错误说明写在方法自己的文档注释里。
- 必须写「为什么」: 错误类型选择的理由、边界值来源、生命周期约束的原因; 只写「做什么」不合格。
- 示例写在 `# Examples` 中, 必须可编译; 不可编译的示例不许写入。

## 4. 行尾注释判据

- 只写原因不写翻译; 判据同总则: 「看起来显然但改错会有后果」。
- 本语言必写情形:
  - `unsafe` 块的上一行或行尾写明该块依赖的不变式, 对应 `# Safety` 的哪一条。
  - 生命周期与借用被刻意放宽处, 写明放宽的边界与调用方义务。
  - `unwrap` / `expect` / `panic!` 处写明确信不会失败的理由; 无理由者改用错误传播。
  - 数值转换、截断、`as` 强转处写明取值范围的来源。
- 免写情形: `#[derive(...)]`、纯转发函数、显然的 `?` 错误传播。
- 裁定结果按总则写入本节, 以「情形 + 结论 + 理由」的案例沉淀。

## 5. 分区标记

- 形式: `// =========** 名称 =========**`, 名称用文件内的实际概念, 如 `常量`、`错误类型`、`公开接口`。
- 标记下一行必须是该分区的文档注释首行; 标记本身不写职责说明。
- 分区顺序: 常量 -> 类型 -> trait -> 实现 -> 测试。
- 测试模块固定 `#[cfg(test)] mod tests` 并置于文件末尾, 其上方写 `// =========** 测试 =========**`。

## 6. 标点与空格

- 注释内标点一律半角; 中文与英文或数字之间留一个空格。
- 文档注释中引用标识符用反引号, 不混用中文引号。
- 全角标点只允许出现在面向用户的字符串字面量内。

## 7. 违规范例(一条)

```rust
// 不合格示例: 公开函数无文档, unsafe 无 # Safety, 未说明返回值
pub unsafe fn read_raw(ptr: *const u8, len: usize) -> usize { ... }
```

问题:

- 公开项缺 `///` 文档注释。
- `unsafe fn` 缺 `# Safety`, 调用方无法判断前置条件。
- 未说明返回值含义与越界行为。

## 8. 交付前自检清单

- [ ] 每个 `.rs` 文件都有 `//!` 八栏文件头, 八项齐全。
- [ ] crate 根写明 lint 配置与理由。
- [ ] `use` 分组正确, 每行注明来源与用途, 无未使用引入与通配引入。
- [ ] 公开项均有 `///`, 含 `# Arguments` / `# Returns` / `# Errors` / `# Panics`。
- [ ] 每个 `unsafe` 都有 `# Safety`, 且与代码实际前置条件一致。
- [ ] 含公开方法的类型写了「方法一览」。
- [ ] 行尾注释只写原因, 无语句翻译。
- [ ] 分区标记形式统一, 下一行为文档注释首行。
- [ ] `cargo clippy -- -D warnings` 与 `cargo test` 均通过。
