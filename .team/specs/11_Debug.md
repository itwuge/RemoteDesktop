# 11 Debug 规范

## 适用范围与效力

- 适用范围: 全语言的开发与排查过程, 包括本地调试、联调、线上问题复现、门禁临时操作与排查结论归档。
- 效力: 违反本文件任一条即判交付不合格, 退回重做, 不计入完成。退回意见必须写明条款编号与位置。
- 与语言细则的关系: 语言细则可补充该语言的调试工具写法, 不得放宽本文的默认级别、残留判定与门禁判据。
- 判定方式: 开关类条款看启动配置与解析实现; 残留类条款看门禁扫描结果; 流程类条款看报告与记录是否齐备。

## 1. 日志开关

条款:

- 开关粒度到模块级, 配置形式为逗号分隔的 `模块:级别` 列表, 例如 `PY_LOG_LEVEL=common.http:DEBUG,platform.runba:INFO`。
- 默认级别为 INFO, 未列出的模块一律按 INFO。
- 全局级别用 `*`, 例如 `PY_LOG_LEVEL=*:DEBUG`; 全局项与模块项同时存在时, 模块项优先。
- 模块名必须与代码目录一致, 用点分路径书写, 如 `common.http` 对应 `common/http/`。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 1.1 | 配置解析支持 `模块:级别` 与 `*:级别` 两种形式 | 不支持即不合格 |
| 1.2 | 默认值为 INFO, 未配置时不输出 DEBUG | 默认 DEBUG 即不合格 |
| 1.3 | 模块项覆盖全局项 | 优先级反向即不合格 |
| 1.4 | 模块名与目录不一致时启动即报错并列出非法项 | 静默忽略即不合格 |
| 1.5 | 级别取值只允许 INFO 与 DEBUG 与 WARNING 与 ERROR | 其他取值静默忽略即不合格 |

Python 正例:

```python
# PY_LOG_LEVEL=common.http:DEBUG,platform.runba:INFO
def resolve_level(logger_name: str, spec: str) -> str:
    rules = dict(item.split(":", 1) for item in spec.split(",") if item)
    if logger_name in rules:
        return rules[logger_name]        # 模块级优先
    return rules.get("*", "INFO")         # 全局或默认 INFO
```

Python 反例:

```python
logging.basicConfig(level=logging.DEBUG)   # 全局默认 DEBUG, 违反 1.2
```

其他语言规则: 各语言提供同语义解析, Rust 与 Go 用环境变量加启动校验, TypeScript 与 Dart 用统一配置对象, Shell 用环境变量并在入口做白名单校验; 模块名映射表必须与目录结构同源, 不得手写第二份。

## 2. dry-run

条款:

- 提供 dry-run 模式, 能跑完全流程的判断逻辑, 但不写盘、不发通知、不提交请求。
- dry-run 必须与正常运行走同一套代码路径, 只在副作用处短路, 禁止复制一份「演练版」流程。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 2.1 | dry-run 下不产生任何文件写入、外部通知、写操作请求 | 出现任一即不合格 |
| 2.2 | dry-run 输出列出「将要写盘的文件路径」「将要发送的通知」「将要提交的请求」 | 缺任一项即不合格 |
| 2.3 | dry-run 与正常运行共用判断逻辑, 差异只在副作用开关 | 另写一套流程即不合格 |
| 2.4 | 全流程完成时退出码为 0, 中途失败为非零 | 恒返回 0 即不合格 |

Python 正例:

```python
if settings.dry_run:
    logger.info("演练: 跳过写盘", extra={"event": "dryrun.skip", "path": str(result_path)})
else:
    result_path.write_text(payload, encoding="utf-8")
```

## 3. 临时调试代码不得入库

条款:

- `print`、`breakpoint()`、`pdb`、`console.log`、`debugger`、`dbg!`、`fmt.Println`、`set -x`, 以及标注为「调试」的 `TODO`, 一律视为残留, 不得入库。
- 门禁必须能扫出上述残留, 命中数必须为 0。

判据:

| 语言 | 扫描模式 | 判定 |
| --- | --- | --- |
| Python | `breakpoint(`、`pdb.set_trace`、`import pdb`、无输出职责的 `print(` | 命中即残留 |
| Rust | `dbg!`、无输出职责的 `println!` | 命中即残留 |
| C 与 C++ | `printf(` 调试行、`getchar()` 停留 | 命中即残留 |
| Go | `fmt.Print`、`log.Print` 调试行、`panic(` 试探 | 命中即残留 |
| Dart | `print(` 调试行、`debugPrint` 非 UI 必需 | 命中即残留 |
| TypeScript | `console.log`、`console.debug`、`debugger`、`alert` | 命中即残留 |
| Shell | `set -x`、调试用 `echo` | 命中即残留 |

补充判据:

- 用户可见输出与调试输出必须区分: 正式输出走结果文件、CLI 输出的显式函数或 logger; 无法区分即按残留处理。
- 不得以注释、`# noqa`、条件包裹等方式保留残留; 门禁不看注释意图, 只按模式计数。
- 本地调试允许临时使用, 提交前必须删除; 差异中存在即不合格。

## 4. 复现三件套

条款:

- 报告问题必须包含三样材料: 环境信息、输入数据、最小步骤。
- 三样不齐, 只能称「偶发」, 不得写成「已定位」。
- 三样齐全且附证据后, 才允许使用「已定位」并给出根因。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 4.1 | 环境信息含系统与运行时版本、依赖版本、相关配置项、`run_id` | 缺项即不齐 |
| 4.2 | 输入数据含账号与参数的脱敏样本、样本文件路径与哈希 | 缺项即不齐 |
| 4.3 | 最小步骤为从干净状态到复现的最短命令序列, 可复制执行 | 缺项即不齐 |
| 4.4 | 三样不齐时报告用词为「偶发」 | 用「已定位」即不合格 |

报告模板:

```text
环境: 系统=Windows 11, 运行时=Python 3.11.6, 依赖=requests 2.31.0, 配置=PY_LOG_LEVEL=*:INFO, run_id=20261108_093102_a1b2
输入: 账号=a0***(脱敏), 参数=mode=full, 样本=state.json sha256=9f2c...
步骤: 1) 清空 logs 与 state 2) 执行 python -m app --dry-run 3) 观察 logs/<run_id>.jsonl 首个 ERROR
```

## 5. 禁止用 assert 做业务校验

条款:

- 业务校验、入参约束、状态前置条件不得使用 `assert`。
- 原因: Python 的 `-O`、C 与 C++ 的 `NDEBUG`、Rust 的 `debug_assert` 在发布构建中会被移除, 校验随构建方式改变而失效。
- 生产校验必须写显式检查并给出可判定的错误, 包含错误码与可读消息。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 5.1 | 业务路径中不存在 `assert` 语句 | 出现即不合格 |
| 5.2 | 参数与状态校验使用显式分支, 抛出或返回明确错误 | 无错误码即不合格 |
| 5.3 | 测试代码中的 `assert` 不受此条限制 | 仅测试文件豁免 |

Python 正例:

```python
def withdraw(amount: int) -> None:
    if amount <= 0:
        raise ValueError("取现金额必须大于 0, 当前值=%d" % amount)   # 显式检查, -O 下仍然生效
```

Python 反例:

```python
def withdraw(amount: int) -> None:
    assert amount > 0   # -O 下被移除, 负值会直接进入后续计算
```

其他语言规则: C 与 C++ 不得用 `assert` 校验外部输入; Rust 生产路径用显式 `if` 返回 `Err`, `debug_assert` 只用于内部不变量; Go 用显式判断返回 `error`; TypeScript 与 Dart 用显式抛出。

## 6. 崩溃必须留栈

条款:

- 程序崩溃或任务异常终止时, 必须留下完整栈, 包含异常类型与消息。
- 禁止捕获后输出「未知错误」「出错了」这类无信息文案。
- 入口兜底处必须打印或记录栈, 口径与 10_日志.md 的异常字段一致。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 6.1 | 崩溃路径的日志或 stderr 含 `stack` 或等价栈文本 | 无栈即不合格 |
| 6.2 | 输出文案中不出现「未知错误」且无栈伴随 | 出现即不合格 |
| 6.3 | 栈经过脱敏, 符合 10_日志.md 第 8 条 | 未脱敏即不合格 |

Python 正例:

```python
except Exception as exc:
    logger.error("运行失败", extra={"event": "run.failed", "exc_type": type(exc).__name__, "stack": traceback.format_exc()})
    raise
```

Python 反例:

```python
except Exception:
    print("未知错误")   # 栈丢失, 无法定位
```

## 7. 排查完成后必须沉淀结论

条款:

- 排查结束必须留下结论, 四栏齐全才算结束: 现象、走过的弯路、真实原因、避坑规则。
- 结论落到问题单或项目内的排查记录, 不只留在聊天记录里。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 7.1 | 四栏各有实质内容, 不是一句话带过 | 缺栏或空泛即不合格 |
| 7.2 | 「真实原因」能对应到具体代码位置或数据 | 无对应即不合格 |
| 7.3 | 「避坑规则」是可执行的检查项, 能加到自检清单或门禁 | 只有「注意一下」这类表述即不合格 |

模板:

```text
现象: 第二批任务全部失败, 结果文件成功数为 0
走过的弯路: 先怀疑接口限流, 加重试后仍失败; 又怀疑账号失效, 换账号仍失败
真实原因: common/http/client.py 的超时配置读取了顶层键, 而配置实际在 platform.runba 下, 取到 None 后按 0 秒处理
避坑规则: 配置读取必须校验键存在, 取不到按「取不到」走兜底并打 WARNING, 不得按 0 处理
```

## 8. 不得为排查关闭门禁

条款:

- 不得为排查方便临时关闭门禁、跳过校验、跳过测试、关闭静态检查。
- 确需临时改动时, 必须满足三条: 记录改动内容与原因、限定影响范围、排查结束立即恢复, 且改动不得提交。
- 门禁配置本身的放宽视为违规, 与代码违规同口径处理。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 8.1 | 排查期间的门禁改动有记录, 含内容、原因、恢复时间 | 无记录即不合格 |
| 8.2 | 交付差异中不含任何门禁放宽或跳过标记 | 含即不合格 |
| 8.3 | 跳过测试、`--no-verify`、关闭 lint、注释掉校验步骤 | 出现即不合格 |

## 9. 交付前自检清单

- [ ] 日志开关为模块级, 默认 INFO, 模块名与代码目录一致, 非法项启动即报错

- [ ] 差异中无 `print`、`breakpoint`、`pdb`、`console.log`、`debugger`、`dbg!`、`set -x` 等残留
- [ ] 问题报告含环境信息、输入数据、最小步骤, 三样不齐时标注「偶发」
- [ ] 业务校验无 `assert`, 使用显式检查并带可判定错误
- [ ] 崩溃路径留有脱敏后的完整栈, 无「未知错误」式文案
- [ ] 排查结论四栏齐全, 避坑规则可执行
