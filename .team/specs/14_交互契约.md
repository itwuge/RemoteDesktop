# 14 交互契约规范

本文只管一句话: 对外只暴露契约, 调用方不需要知道内部如何实现。契约有两条落地路径, Web 项目暴露为 HTTP API, 桌面软件暴露为命令函数, 两条路径共用同一套原则, 落地形式不同。本文管契约形状, 规定对外暴露什么、入参出参长什么样、错误怎么返回; 不管异常捕获策略, 不管日志格式, 也不管协作流程。

## 1. 适用与边界

### 1.1 两条路径各自适用什么

| 项目形态 | 适用条款 | 不适用条款 |
| --- | --- | --- |
| Web 项目 | 第 2 条通用原则与第 4 条 HTTP API 全部约定 | 第 3 条命令函数约定 |
| 桌面软件 | 第 2 条通用原则与第 3 条命令函数全部约定 | 第 4 条 HTTP API 约定 |

- Web 项目的全部对外调用面按 HTTP API 判: 页面、移动端、第三方系统对同一组接口的调用一致, 不得为某一端另开一套形状不同的接口。
- 桌面软件的对外调用面按命令函数判: 界面层与本机内部其他进程一律通过命令函数交互。
- 桌面软件不强制内部采用 MVC 还是 MVVM。本文只规定界面层与命令层的边界: 界面层只做收集参数、调用一个命令函数、呈现结果三件事; 界面层内部怎么拆 Model、View、ViewModel 归 M03 架构师与对应语言专家定, 写进契约文档, 本文不判。
- 两种形态并存的项目, 两条路径分别按各自条款判, 不得拿其中一条的标准去判另一条。

### 1.2 与既有规范的分工

| 文件 | 管什么 | 本文不管什么 |
| --- | --- | --- |
| 00_总则 与 01 至 08 语言细则 | 代码写成什么样: 文件头、导入、注释、标点 | 契约形状 |
| 09_异常捕获 | 异常在哪捕获、转换后怎么保留原因链、重试边界、用户可见失败文案保持原样 | 返回结构长什么样 |
| 10_日志 | 日志格式、字段、级别、脱敏与检索 | 契约字段与对外文案 |
| 11_Debug | 调试开关、dry-run、复现材料与门禁纪律 | 契约形状 |
| 12_团队规范 | 谁派活、谁评审、怎么开会交接 | 契约形状 |
| 13_指挥规范 | 任务卡、批次、监督、收单与汇报 | 契约形状 |
| 本文 | 契约形状: 对外暴露什么、入参出参长什么样、错误怎么统一返回 | 异常捕获策略、日志格式、协作流程 |

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 1.1 | 项目形态与所引条款一致: Web 项目引第 4 条, 桌面软件引第 3 条 | 引错条款或两条混用即不合格 |
| 1.2 | 契约文档里能指认到本文的条款号 | 指认不到即不合格 |
| 1.3 | 本文条款与 09_异常捕获、10_日志 冲突时按分工分别判定 | 用本文放宽异常捕获或日志要求即不合格 |

正例: 桌面项目的新增账号动作, 契约只声明 `create_account(name: str) -> CommandResult`, 并写明失败时 `error_code` 的取值表。

反例: 契约写成「新增账号(数据库表 accounts, 主窗口对象)」, 把存储实现与界面控件一起写进对外声明, 同时违反 1.1 与第 2 条。

## 2. 通用原则

两条路径共用以下四条, 缺任一条即该契约不合格。

- 先定契约、再写实现。契约未冻结不得开工写实现; 契约与实现分别落在不同文件, 契约文件里不出现实现代码。
- 实现类不得被上层直接引用。上层只依赖接口声明, 由装配处决定用哪个实现。
- 契约只描述行为, 不泄漏实现细节。契约声明中不出现 SQL 语句与表名、文件路径、界面控件类型、HTTP 状态码。
- 错误统一成一种返回结构, 不允许裸异常穿透层边界。任何一层对外只交出统一结果, 内部异常在边界处转换成该结果。
- 依赖只向下注入, 禁止在函数内部直接构造具体实现。数据库连接、网络客户端、文件句柄一律由构造参数或装配处传入。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 2.1 | 契约文件中不出现 `SELECT`、`INSERT`、`UPDATE`、`DELETE` 等 SQL 关键字与表名 | 命中即不合格 |
| 2.2 | 契约声明中不出现绝对或相对文件路径、控件类名、窗口类名 | 命中即不合格 |
| 2.3 | 契约声明中不出现 HTTP 状态码字面量, 状态语义只体现在统一结果的错误码与文案 | 命中即不合格 |
| 2.4 | 上层代码不出现实现类名, 只出现接口名; 以 `import` 与 `new` 或实例化为准 | 命中即不合格 |
| 2.5 | 函数体内不出现直接构造具体实现, 如 `new SqliteRepo()`、`sqlite3.connect(...)`、`http.Client()` | 命中即不合格 |
| 2.6 | 层边界对外只交出统一结果结构, 不向上抛原生异常类型 | 命中即不合格 |

Python 正例:

```python
class AccountRepository(Protocol):
    """账号存储的对外契约: 只承诺行为, 不承诺用哪种存储."""

    def insert(self, name: str) -> str:
        """写入一个账号并返回账号标识."""


class AccountService:
    """账号相关命令的装配点: 依赖由外部传入, 本类不构造实现."""

    def __init__(self, repo: AccountRepository) -> None:   # 依赖向下注入
        self._repo = repo
```

Python 反例:

```python
def create_account(name: str) -> str:
    db = sqlite3.connect("data/app.db")          # 函数内直接构造实现, 存储路径也泄漏
    db.execute("INSERT INTO accounts(name) VALUES (?)", (name,))   # SQL 出现在契约实现里
    return name
```

## 3. 桌面软件: 命令函数约定

本节是本文重点。桌面软件的全部对外能力都以命令函数暴露, 界面层不直接触达业务与数据。

### 3.1 一个用户动作对应一个命令函数

- 一个用户动作只对应一个命令函数, 一个命令函数只承担一个动作, 不得一个函数按参数分叉做多件事。
- 函数名动词开头, 全小写, 词间用下划线, 形式为「动词加名词」。
- 取消、确认、进度查询同样各有独立函数, 不得塞回原函数靠参数区分。
- 事件命名归界面层, 命令层不得出现 `on_click`、`handle_xxx`、`do_stuff` 这类命名。

命名示例表:

| 用户动作 | 命令函数名 | 说明 |
| --- | --- | --- |
| 新建账号 | `create_account` | 新建单个资源 |
| 删除账号 | `delete_account` | 删除单个资源 |
| 修改账号备注 | `update_account_note` | 只改一份数据 |
| 查询账号列表 | `list_accounts` | 列表查询 |
| 开始签到 | `start_checkin` | 启动长任务 |
| 停止任务 | `stop_task` | 停止长任务 |
| 查询任务进度 | `get_task_progress` | 长任务配套查询 |
| 取消任务 | `cancel_task` | 长任务配套取消 |
| 确认删除 | `confirm_delete_account` | 承接需确认结果 |
| 打开设置页 | `open_settings` | 打开界面但动作由命令层发起 |
| 导出报告 | `export_report` | 产出文件 |
| 校验路径 | `validate_path` | 纯校验, 无副作用 |

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 3.1.1 | 每个命令函数名首词属于动词集: create、delete、update、list、get、start、stop、cancel、confirm、open、close、export、import、validate、refresh、apply | 首词不在集合内即不合格 |
| 3.1.2 | 命令函数名中不出现 `on_`、`handle_` 前缀与 `do` 开头的含糊命名 | 命中即不合格 |
| 3.1.3 | 一个函数名只对应一个动作, 参数中不出现「模式」「类型」这类用于分叉动作的开关 | 出现动作分叉即不合格 |

### 3.2 入参只接受原始值与枚举

- 允许的入参类型: 原始值 (字符串、整数、浮点数、布尔、空值)、枚举, 以及仅由原始值与枚举组成的值对象。
- 禁止的入参类型: 控件、窗口、事件对象、界面框架的模型对象、数据库连接、文件句柄、网络客户端。
- 需要多个字段时用一个值对象承载, 值对象字段同样只允许原始值与枚举。
- 界面层负责从控件取值并组装成原始值或值对象, 命令层不读控件。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 3.2.1 | 命令函数签名中不出现控件类、窗口类、事件类、连接类、句柄类 | 命中即不合格 |
| 3.2.2 | 函数体内不出现控件取值, 如 `.text()`、`.value`、`.selectedIndex`、`.get()` | 命中即不合格 |
| 3.2.3 | 禁止类型出现在值对象字段中 | 视为间接违反, 不合格 |

反例:

```python
def create_account(self, window: QMainWindow, event: QMouseEvent) -> CommandResult:
    name = window.name_input.text()   # 入参带窗口与事件, 契约绑死界面框架, 换界面即重写
    enabled = window.enabled_box.isChecked()
```

正例:

```python
def create_account(self, name: str, enabled: bool) -> CommandResult:
    """按原始值建账号; 控件取值由界面层完成后传入."""
```

### 3.3 返回统一结果结构

命令函数一律返回同一结构, 五个字段固定, 不得另起结构或按函数自定义字段名:

| 字段 | 类型 | 必填 | 含义 | 判据 |
| --- | --- | --- | --- | --- |
| `ok` | 布尔 | 是 | 是否成功 | 缺失或为空即不合格 |
| `message` | 字符串 | 是 | 用户可见文案, 由界面层原样呈现 | 空串即不合格; 文案改动须按 09_异常捕获 第 8 条走需求单 |
| `error_code` | 字符串 | 否 | 仅在调用方需要分支判断时给码, 其余留空 | 为整齐逐条编号即不合格 |
| `data` | 对象 | 否 | 成功时的结果数据, 字段在契约中列明 | 失败时不得携带可被误当成功的数据 |
| `confirm` | 对象 | 否 | 需确认时出现, 含提示文案与确认令牌 | 出现时 `ok` 必须为假, 界面层据其非空判定询问 |

Python 示例:

```python
from dataclasses import dataclass
from typing import Any


@dataclass(frozen=True)
class CommandResult:
    """命令函数统一返回结构, 界面层只读不改."""

    ok: bool                                     # 是否成功
    message: str                                 # 用户可见文案, 界面层原样呈现
    error_code: str | None = None                # 仅调用方需分支判断时给码
    data: dict[str, Any] | None = None           # 成功时的结果数据
    confirm: dict[str, str] | None = None        # 需确认时非空, 由界面层提问
```

Dart 示例:

```dart
class CommandResult<T> {
  const CommandResult({
    required this.ok,
    required this.message,
    this.errorCode,
    this.data,
    this.confirm,
  });

  final bool ok;                   // 是否成功
  final String message;            // 用户可见文案, 界面层原样呈现
  final String? errorCode;         // 仅调用方需分支判断时给码
  final T? data;                   // 成功时的结果数据
  final ConfirmRequest? confirm;   // 需确认时非空, 由界面层提问
}
```

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 3.3.1 | 每个命令函数的返回类型都是同一结果类型 | 出现第二种返回类型即不合格 |
| 3.3.2 | 每个返回分支都构造完整结果, 五字段中 `ok` 与 `message` 必填 | 出现 `return None`、`return True`、裸返回即不合格 |
| 3.3.3 | `error_code` 只在调用方需要分支时出现, 其余失败只给 `message` | 每条失败都编号即不合格 |
| 3.3.4 | `confirm` 非空的返回, `ok` 为假 | 违反即不合格 |

### 3.4 函数内禁止三件事

- 不得弹窗: 命令函数不打开任何对话框、提示框、确认框。
- 不得阻塞界面线程: 耗时动作交给任务层异步执行, 命令函数不得 `sleep`、不得同步等待外部返回、不得在主线程做重活。
- 不得直接写日志给用户看: 日志按 10_日志 的结构化格式落盘, 面向用户的结果只经 `message` 返回, 不得用 `print`、`echo`、`console.log` 充当用户提示。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 3.4.1 | 命令层文件中无弹窗类调用: `QMessageBox`、`MessageBox`、`AlertDialog`、`showDialog`、`messagebox.` | 命中即不合格 |
| 3.4.2 | 命令层文件中无阻塞调用: `sleep`、`Thread.sleep`、`wait` 同步等待、`input()` | 命中即不合格 |
| 3.4.3 | 命令层文件中无面向用户的打印: `print(`、`console.log(`、`System.out` | 命中即不合格 |

### 3.5 需确认的交互由界面层询问

- 命令函数只返回「需确认」结果, 不自己弹确认框, 不得自己替用户做决定。
- `confirm` 内至少含两项: 提示文案, 以及用于二次提交的确认令牌。
- 界面层据 `confirm` 非空弹出询问; 用户确认后调用配套的确认函数, 用户取消则不调用任何函数。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 3.5.1 | `confirm` 内能指认提示文案与确认令牌两项 | 缺项即不合格 |
| 3.5.2 | 存在与首次动作一一对应的确认函数, 如 `delete_account` 对应 `confirm_delete_account` | 无确认函数即不合格 |
| 3.5.3 | 确认令牌只能由服务端或命令层签发, 界面层不得自行拼造 | 命中即不合格 |

正例: `delete_account` 返回 `CommandResult(ok=False, message="删除后不可恢复", confirm={"prompt": "确认删除账号 u_1001?", "token": "del-acc-1001"})`, 界面层据 `confirm` 弹询问, 用户确认后调 `confirm_delete_account(token="del-acc-1001")`。

反例: 命令函数内直接 `QMessageBox.question(self.window, "确认", "确认删除?")`, 把询问与业务判断一起塞进命令层, 界面层只剩被动接受结果。

### 3.6 长任务必须返回任务句柄

- 长任务指耗时超过一次界面刷新的动作, 判定以契约文档列明的时长阈值为准, 阈值由 M03 写入契约。
- 长任务命令必须返回任务句柄, 句柄放在 `data` 内, 至少含任务标识与总量; 不得只返回「已开始」而无句柄。
- 必须提供配套的进度查询函数与取消函数, 二者入参为任务标识, 返回同一结果结构。
- 进度查询返回的 `data` 至少含四项: 已完成数、总量、状态、可取消标记; 状态用枚举, 不用魔法数字。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 3.6.1 | 每个长任务命令的返回 `data` 中可指认任务标识字段 `task_id` | 缺失即不合格 |
| 3.6.2 | 每个长任务均有对应的进度查询函数与取消函数 | 缺任一即不合格 |
| 3.6.3 | 进度查询返回的状态为枚举值, 如 `pending`、`running`、`canceled`、`done`、`failed` | 用整数比较即不合格 |
| 3.6.4 | 长任务命令的 `message` 不是仅有「已开始」一类文案, 必须同时给出任务标识或总量 | 缺项即不合格 |

正例:

```python
def start_checkin(self, account_id: str) -> CommandResult:
    task = self._runner.start(account_id)   # 立即返回句柄, 不阻塞界面线程
    return CommandResult(
        ok=True,
        message="签到任务已启动, 共 32 项",
        data={"task_id": task.id, "total": task.total},
    )
```

反例:

```python
def start_checkin(self, account_id: str) -> CommandResult:
    return CommandResult(ok=True, message="已开始")   # 无句柄, 界面层无法查进度也无法取消
```

### 3.7 界面层只做三件事

界面层只允许做三件事: 收集参数、调用一个命令函数、呈现结果。任何第四件事都属越界。

- 不写业务判断: 不比较状态魔法数字, 不判断是否已签到、余额是否足够、权限是否具备。
- 不拼 SQL, 不直接读写数据库与文件。
- 不发 HTTP 请求, 不解析远端原始响应。
- 不自己组织用户可见文案, 只原样呈现 `message`, 需要拼接时只允许加界面装饰, 不改文案本身。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 3.7.1 | 界面层文件中无状态魔法数字比较, 如 `== 3`、`== 2`、`status > 1` | 命中即不合格 |
| 3.7.2 | 界面层文件中无 SQL 关键字与直接存储调用 | 命中即不合格 |
| 3.7.3 | 界面层文件中无 HTTP 客户端调用: `requests.`、`http.`、`fetch(`、`axios` | 命中即不合格 |
| 3.7.4 | 界面层不自行改写 `message`, 文案以命令函数返回为准 | 改写即不合格 |
| 3.7.5 | 界面层每次交互只调用一个命令函数, 需要两次调用时必须由命令层再出一个组合函数 | 一处调用两个以上命令函数即不合格 |

### 3.8 按钮到命令函数的完整示例

以「开始签到」按钮为例, 界面代码与命令函数分列。

界面层:

```python
def on_checkin_clicked(self) -> None:
    """界面层只做三件事: 收参数、调一个命令函数、呈现结果."""

    account_id = self.selected_account_id()                  # 一: 收集参数
    result = self._commands.start_checkin(account_id)         # 二: 调用一个命令函数
    self._show_result(result)                                 # 三: 呈现结果, 只读不改
```

命令层:

```python
class CheckinCommands:
    """签到相关命令: 对外只暴露函数, 内部实现不向上暴露."""

    def __init__(self, repo: AccountRepository, runner: CheckinRunner) -> None:   # 依赖注入
        self._repo = repo
        self._runner = runner

    def start_checkin(self, account_id: str) -> CommandResult:
        """校验入参后启动长任务, 立即返回任务句柄."""

        account = self._repo.find(account_id)          # 内部查询, 界面层不可见
        if account is None:
            return CommandResult(ok=False, message="账号不存在, 请刷新后重试", error_code="ACCOUNT_NOT_FOUND")
        task = self._runner.start(account_id)
        return CommandResult(ok=True, message="签到任务已启动", data={"task_id": task.id, "total": task.total})
```

判据: 界面层文件中出现的命令函数调用数量为 1, 命令层文件中不出现任何界面类名, 两者以文件为界即可核对。

## 4. Web 项目: HTTP API 约定

### 4.1 统一响应包络

所有响应一律为三字段包络: `code`、`message`、`data`。

成功示例:

```json
{"code": 0, "message": "签到成功", "data": {"account_id": "u_1001", "points": 5}}
```

失败示例:

```json
{"code": 40901, "message": "今日已签到, 请勿重复操作", "data": null}
```

- 三字段恒出现, 失败时 `data` 写 `null`, 不得省略字段本身。
- `code` 为 0 表示成功, 非 0 表示失败; 不得用布尔字段代替。
- `message` 为用户可读中文, 与 09_异常捕获 第 8 条的用户可见文案基线逐字一致。
- 顶层不得是数组或裸标量, `data` 才承载列表与对象。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 4.1.1 | 逐响应做 JSON 解析与键检查, 三字段齐全 | 缺任一即不合格 |
| 4.1.2 | 响应顶层类型为对象 | 数组或标量即不合格 |
| 4.1.3 | 失败响应 `data` 为 `null` | 失败仍带业务数据即不合格 |

### 4.2 资源路径与请求方法

资源路径用复数名词, 写操作用 POST, 读操作用 GET。

| 操作 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 新增 | POST | `/v1/accounts` | body 为待建资源字段 |
| 查询单个 | GET | `/v1/accounts/{id}` | 资源标识在路径 |
| 查询列表 | GET | `/v1/accounts` | 分页与筛选走查询参数 |
| 修改 | POST | `/v1/accounts/{id}/update` | body 只带变更字段 |
| 删除 | POST | `/v1/accounts/{id}/delete` | 写操作, 幂等键必带 |

- 资源段一律复数, 写 `accounts` 不写 `account`。
- 动作段用动词原形, 放在资源段之后; 不得出现 `/v1/getAccountList` 这类动词开头的路径。
- 读写区分只按方法与路径判定, 不靠自定义参数区分。
- 路径不得携带凭证、不得携带业务文案。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 4.2.1 | 路径首段为 `/v1` | 缺失即不合格 |
| 4.2.2 | 资源段为复数名词 | 单数即不合格 |
| 4.2.3 | 写操作使用 POST, 读操作使用 GET | 用 GET 传递写意图即不合格 |
| 4.2.4 | 路径中不出现动词开头的动作段 | 命中即不合格 |

### 4.3 错误码口径

- 只在调用方需要分支判断时给固定错误码。典型情形: 需要据码切换界面状态的「今日已签到」「账号不存在」「需重新登录」。
- 其余失败只给文案, 不给码。不得为整齐给每条错误编号, 不得按异常类型批量发码。
- 错误码划分与 09_异常捕获 第 5 条一致: 取不到与出错不得共用同一个码。
- 错误码不得泄漏实现信息: 不出现异常类名、堆栈、SQL 文案、文件路径。
- 敏感信息按 09_异常捕获 第 7 条与 10_日志 第 8 条处理, 响应体里不得出现凭据原文。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 4.3.1 | 每个 `code` 都能指认到一个需要分支判断的调用方场景 | 指认不到即视为多余编号, 不合格 |
| 4.3.2 | 取不到与出错使用不同 `code` | 共用即不合格 |
| 4.3.3 | 响应 `message` 中不含异常类名、堆栈、SQL 与文件路径 | 命中即不合格 |

正例:

```json
{"code": 40901, "message": "今日已签到, 请勿重复操作", "data": null}
```

调用方据 40901 隐藏签到按钮, 无需解析文案。

反例:

```json
{"code": 1001, "message": "签到失败: sqlite3.IntegrityError: UNIQUE constraint failed", "data": null}
```

码无分支价值, 文案泄漏存储实现与异常类型, 同时违反 4.3.1 与 4.3.3。

### 4.4 分页、时间、排序与筛选

参数名固定, 不得各接口自取名。

| 类别 | 参数名 | 规则 |
| --- | --- | --- |
| 页码 | `page` | 从 1 起, 缺省 1 |
| 每页条数 | `page_size` | 缺省 20, 上限 100, 超限按上限处理 |
| 排序字段 | `sort` | 字段名, 多字段用逗号分隔 |
| 排序方向 | `order` | `asc` 或 `desc`, 缺省 `asc` |
| 筛选 | 与响应字段同名 | 如 `status=active`; 不得用 `filter[status]` 或 `q` 拼串 |

- 分页响应的 `data` 固定四字段: `items`、`total`、`page`、`page_size`。
- 时间统一为 ISO 8601 带时区偏移, 例 `2026-11-09T10:30:00+08:00`, 与 10_日志 的 `ts` 同口径; 纯日期字段用 `YYYY-MM-DD`。
- 禁止本地朴素时间、禁止毫秒时间戳、禁止同一接口混用多种时间格式。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 4.4.1 | 列表接口的参数名与上表逐字一致 | 出现别名即不合格 |
| 4.4.2 | 分页响应 `data` 四字段齐全 | 缺任一即不合格 |
| 4.4.3 | 每个时间字段都能解析为带偏移的时间 | 解析不出偏移即不合格 |

### 4.5 幂等键

- 所有写操作必须支持幂等键, 请求头名固定为 `Idempotency-Key`。
- 取值由调用方生成, 为 16 至 64 位的随机串或 UUID, 同一业务请求重试时复用同一个值。
- 去重语义: 同一幂等键、同方法、同路径、同请求体摘要, 在 24 小时内只执行一次, 后续请求直接返回首次结果, 结果含相同的 `code` 与 `data`。
- 同一幂等键配不同请求体, 视为冲突: 返回失败, 文案「幂等键已用于其他请求」, 不得执行本次写操作。
- 写请求缺少幂等键: 拒绝执行, 返回失败, 文案「缺少幂等键」。
- 幂等键不得进入 URL, 不得写入日志原文, 按凭据口径脱敏。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 4.5.1 | 每个写接口的契约文档写明 `Idempotency-Key` 与去重时长 | 未写明即不合格 |
| 4.5.2 | 实测同一键连发两次, 第二次响应与第一次一致且副作用只发生一次 | 副作用发生两次即不合格 |
| 4.5.3 | 缺键与冲突两种情形各有固定失败文案 | 缺项即不合格 |

### 4.6 版本前缀与破坏性变更

- 路径首段固定 `/v1`, 不得省略; 版本只认路径前缀, 不以请求头或查询参数表达版本。
- 破坏性变更升 `/v2`: 删除字段、改字段语义、改路径、改错误码含义, 四类任一即属破坏性。
- 非破坏性变更可在 `/v1` 内进行: 新增可选字段、新增资源、新增错误码。
- 旧版本至少并行一个发布周期, 下线日期写入契约文档, 下线前通知全部调用方。
- 同一路径不得同时接受两种形态的请求体。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 4.6.1 | 所有路径首段为 `/v1` 或 `/v2` | 缺版本段即不合格 |
| 4.6.2 | 破坏性变更均有新版路径与旧版下线日期 | 缺任一即不合格 |
| 4.6.3 | 版本切换不依赖请求头或查询参数 | 命中即不合格 |

### 4.7 鉴权头与凭证

- 鉴权统一走请求头 `Authorization: Bearer <token>`, 不得自定义鉴权头。
- 凭证只放请求头, 不得出现在 URL、查询参数、请求体与响应体。
- 凭证不得进入日志, 日志侧按 10_日志 第 8 条做首尾四位加 `***` 掩码。
- 鉴权失败返回标准包络, `code` 非 0, `message` 为用户可读文案, `data` 为 `null`; 不得返回登录页 HTML 或裸 401 空体。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 4.7.1 | 接口契约写明鉴权头名与凭证位置 | 未写明即不合格 |
| 4.7.2 | 路径、查询参数、请求体、响应体中无凭证原文 | 命中即不合格 |
| 4.7.3 | 鉴权失败响应符合 4.1 包络 | 返回裸状态码或 HTML 即不合格 |

正例:

```
Authorization: Bearer 8f2c***9d1a
GET /v1/accounts?page=1&page_size=20
```

反例:

```
GET /v1/accounts?token=8f2c9d1a5b7e...
```

凭证进入 URL 会被网关、代理与访问日志原样记录, 同时违反 4.7.2 与 10_日志 第 8 条。

### 4.8 跨域、缓存与安全头归 W01

- 跨域白名单、缓存头、安全头 (CSP、HSTS、`X-Content-Type-Options` 等) 的策略取值归 W01, 依据为 员工\22_W01_Web专家.md 与契约评审结论。
- 本文只规定这些策略必须在契约文档中登记归属: 写明由谁定、取值落在哪份文件、谁复核。
- 不得由本文推导出任何具体取值; 涉及安全头的改动须同步 S01 复核。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 4.8.1 | 契约文档中每项跨域、缓存与安全头策略都能指认到 W01 的既定口径 | 指认不到即不合格 |
| 4.8.2 | 契约文档未把具体取值当作本文要求 | 记为本文要求即不合格 |

## 5. 八语言接口写法对照表

下列写法只规定契约声明形态与实现隐藏方式, 具体语法细节仍按对应语言细则。

| 语言 | 契约声明写法 | 实现类如何被隐藏 | 判据 |
| --- | --- | --- | --- |
| Python | `Protocol` 或 `ABC` 声明接口, 构造函数注入 | 实现类放内部模块, 上层只 import 接口所在模块, 实现类名不出现在界面层 | 上层文件中 grep 不到实现类名 |
| Rust | `trait` 声明接口, 依赖处用 `Box<dyn Trait>` 或泛型注入 | 实现 `struct` 留在 crate 内部模块, 只导出 trait 与工厂函数 | `pub use` 中不出现实现 struct |
| C | 头文件只声明不透明句柄与函数指针表 | 实现函数在 `.c` 内声明 `static`, 对外只给句柄与表 | 头文件中无内部结构体定义 |
| C++ | 纯虚基类声明接口, 上层持有 `std::unique_ptr<接口>` | 实现类定义在 `.cpp` 或内部目录, 头文件只留纯虚基类 | 头文件不含实现类定义 |
| Go | `interface` 由调用方包定义, 构造函数注入 | 实现结构体字段非导出, 只导出构造函数 | 包外无法直接构造实现结构体 |
| Dart | `abstract class` 声明接口, 构造注入 | 实现类放内部目录, 界面层只 import 抽象类所在文件 | 界面层文件中 grep 不到实现类名 |
| TypeScript | `interface` 声明, 构造函数参数注入 | 实现类不由入口文件导出, 上层 `import type` 只取接口 | 入口 `index` 导出中不出现实现类 |
| Shell | 函数契约: 位置参数、退出码、stdout 格式三项写进函数注释 | 内部函数加 `_` 前缀, 对外只调用导出的入口函数, 实现细节不进 stdout | 入口函数之外的函数名不被外部脚本调用 |

- Shell 的函数契约三项缺一即不合格: 入参顺序与含义、退出码含义 (0 成功、非 0 失败且区分取不到与出错)、stdout 的固定格式。
- 八种语言的实现隐藏判据均可用 grep 或导出面检查执行, 不依赖人工印象。

## 6. 违规范例

六条均为高频问题, 每条给错误写法与正确写法。

### 6.1 界面里直接查数据

错误写法:

```python
def on_refresh_clicked(self) -> None:
    rows = sqlite3.connect("data/app.db").execute("SELECT * FROM accounts").fetchall()   # 界面层直连存储
    self.table.set_rows(rows)
```

正确写法:

```python
def on_refresh_clicked(self) -> None:
    result = self._commands.list_accounts()   # 界面层只调一个命令函数
    self._show_result(result)
```

判据: 界面层文件中 grep 不到 SQL 关键字与 `connect(`。

### 6.2 界面里判断业务状态

错误写法:

```python
if account.status == 3:            # 3 是「已签到」, 界面层拿魔法数字做业务判断
    self.checkin_button.hide()
```

正确写法:

```python
result = self._commands.get_checkin_state(account_id)   # 业务判断归命令层
if result.ok and result.data["checked_in"]:
    self.checkin_button.hide()                          # 界面只按契约字段呈现
```

判据: 界面层文件中 grep 不到 `== 3`、`== 2` 一类状态数字比较; 布尔语义由契约字段给出。

### 6.3 命令函数里弹对话框

错误写法:

```python
def delete_account(self, account_id: str) -> CommandResult:
    if QMessageBox.question(self.window, "确认", "确认删除?"):   # 命令层弹窗, 界面框架被绑死
        self._repo.delete(account_id)
```

正确写法:

```python
def delete_account(self, account_id: str) -> CommandResult:
    return CommandResult(
        ok=False,
        message="删除后不可恢复",
        confirm={"prompt": "确认删除该账号?", "token": f"del-{account_id}"},
    )
```

判据: 命令层文件中 grep 不到弹窗类调用; `confirm` 非空时 `ok` 为假。

### 6.4 命令函数只返回「已开始」

错误写法:

```python
def start_checkin(self, account_id: str) -> CommandResult:
    threading.Thread(target=self._runner.run, args=(account_id,)).start()
    return CommandResult(ok=True, message="已开始")   # 无句柄, 界面层无法查进度与取消
```

正确写法:

```python
def start_checkin(self, account_id: str) -> CommandResult:
    task = self._runner.start(account_id)              # 任务层签发句柄, 不阻塞界面线程
    return CommandResult(ok=True, message="签到任务已启动", data={"task_id": task.id, "total": task.total})
```

判据: 长任务的返回 `data` 中能指认 `task_id`, 且存在对应的、以 `task_id` 为入参的查询与取消函数。

### 6.5 远程接口返回裸数组无包络

错误写法:

```json
[{"account_id": "u_1001", "points": 5}]
```

调用方无法区分「成功且结果为空」与「失败」, 也无处承载文案与错误码。

正确写法:

```json
{"code": 0, "message": "查询成功", "data": {"items": [{"account_id": "u_1001", "points": 5}], "total": 1, "page": 1, "page_size": 20}}
```

判据: 响应顶层类型为对象, 三字段齐全; 列表放在 `data.items`。

### 6.6 错误直接抛裸异常穿透层边界

错误写法:

```python
def export_report(self, path: str) -> CommandResult:
    return open(path, "w").write("...")   # 失败时抛 OSError 直穿到界面层
```

正确写法:

```python
def export_report(self, path: str) -> CommandResult:
    try:
        self._writer.write(path)
    except OSError as exc:
        logger.error("导出失败", extra={"event": "report.export.failed", "exc_type": type(exc).__name__})
        return CommandResult(ok=False, message="导出失败, 请检查目标目录是否可写", error_code="EXPORT_FAILED")
    return CommandResult(ok=True, message="导出完成", data={"path": path})
```

判据: 命令层文件中不出现向上抛原生异常的 `raise` 作为对外出口; 每处捕获都有 09_异常捕获 第 3 条四选一中的处置证据。
