# 09 异常捕获规范

## 适用范围与效力

- 适用范围: 全语言。Python、Rust、C、C++、Go、Dart、TypeScript、Shell, 以及 CI 内联脚本, 一律适用, 不区分服务端、客户端、工具与测试辅助代码。
- 覆盖对象: 生产代码、脚本、构建与发布脚本、运维脚本。
- 效力: 违反本文件任一条即判交付不合格, 退回重做, 不计入完成。退回意见必须写明文件名、条款编号与代码位置(文件、行号), 不得只写「异常处理不规范」。
- 与语言细则的关系: 语言细则只能补充语法写法, 不得放宽本文判据; 冲突时以本文件为准, 由该语言专家提交细则修订。
- 判定方式: 每条均给出可判定判据。判据只按字面执行, 不按作者意图解释; 三种验证途径为读代码、看差异、跑门禁, 任一途径命中即成立。

## 1. 核心原则: 捕获即承诺

- 捕获一个异常, 等于向上层承诺「这件事我处理了」。承诺必须有对应动作。
- 不打算处理的异常不许捕获, 让它传播到有能力处置的层。
- 处置动作只承认第 3 条列出的四种形态, 不落入这四类的捕获一律视为未处置。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 1.1 | 每个捕获块内能定位到四选一处置动作的证据 | 无证据即不合格 |
| 1.2 | 捕获块存在与处置无关的理由, 如「让程序别崩」「先包起来以后再说」 | 理由不成立, 不合格 |
| 1.3 | 捕获范围覆盖了不产生该异常的主流程语句 | 视为过度捕获, 不合格 |

Python 正例:

```python
try:
    resp = client.post(url, timeout=10)
except TimeoutError as exc:
    raise UpstreamUnavailable("签到接口超时") from exc   # 本层无法处置: 转换并上抛
```

Python 反例:

```python
try:
    resp = client.post(url, timeout=10)
except TimeoutError:
    pass   # 捕获即丢弃, 无处置动作, 不合格
```

其他语言规则:

- Rust: 用 `?` 向上传播优于就地捕获; `Result` 不得用 `let _ =` 丢弃, 不得用 `.ok()` 把错误转成 `None` 后继续。
- C: 逐个检查返回值与 `errno`, 不得用 `(void)` 强转忽略错误码, 不得在错误分支里静默 `continue`。
- C++: 在 IO 边界捕获具体异常类型, 不得就地 `catch (...)` 后空块返回默认值。
- Go: 每个 `err` 必须被返回、包装或显式处置; 禁止 `_ = err` 与空的 `if err != nil {}`。
- Dart: 禁止 `catch (e) {}` 空块; 局部无法处置时必须 `rethrow` 并保留栈。
- TypeScript: 禁止空 `catch {}`; 不得捕获后返回 `null` 冒充成功。
- Shell: 不得用 `|| true`、`2>/dev/null` 掩盖失败; 关键命令必须检查退出码。

## 2. 禁止项

以下写法直接判不合格, 不进入讨论:

| 编号 | 禁止写法 | 说明 |
| --- | --- | --- |
| 2.1 | 裸 `except:` 或等价的全捕获, 后接 `pass` | 吞掉包括键盘中断与退出信号在内的一切异常 |
| 2.2 | 任意捕获后仅 `continue` | 循环继续, 失败被抹平, 汇总里看不到 |
| 2.3 | 捕获后 `return None`、`return []`、`return {}`、`return false` 冒充成功 | 上层无法区分成功与失败 |
| 2.4 | 捕获后只 `print` 不记录、不处置 | 调试输出不是处置 |
| 2.5 | 捕获块包住整段主流程, 用一个异常类型兜住全部逻辑 | 过度捕获, 掩盖真实缺陷 |
| 2.6 | 捕获后设置一个布尔标志但不影响返回值与日志 | 标志无人消费, 等于空块 |

判据:

- 捕获块内有效语句只有 `pass`、`continue`、`return None`、`return null`、`return`、空块时, 直接判 2.1 至 2.3。
- 全语言禁用裸捕获作为常规手段。唯一例外是第 9 条的入口兜底与任务单元隔离, 且必须带完整记录与失败标记, 缺一不算例外。

Python 反例:

```python
for account in accounts:
    try:
        do_checkin(account)
    except Exception:
        continue   # 2.2: 失败被吞, 汇总仍显示全部成功
```

```python
try:
    data = load_state()
except ValueError:
    return None   # 2.3: 上层拿到 None 会当成首次运行, 掩盖数据损坏
```

Python 正例(仅限任务单元隔离边界):

```python
for account in accounts:
    try:
        summary.add(do_checkin(account))
    except Exception as exc:   # 任务单元隔离: 单账号失败不得中断整批
        logger.error("账号签到失败", extra={"event": "checkin.failed", "account": account.id})
        summary.add_failed(account, reason=str(exc))
```

其他语言规则:

- Rust: `unwrap_or_default()` 用在可能失败的业务路径上等同 2.3; `let _ =` 等同 2.1。
- C: 空 `if (ret != 0) {}` 等同 2.1; `goto` 跳到成功标签绕过错误处理等同 2.3。
- C++: `catch (...) { return {}; }` 等同 2.1 加 2.3。
- Go: `if err != nil { continue }` 等同 2.2; `_ = json.Unmarshal(...)` 等同 2.1。
- Dart: `catch (_) { return null; }` 等同 2.3。
- TypeScript: `try { ... } catch { return null; }` 等同 2.3。
- Shell: `cmd || continue` 与 `cmd || return 0` 分别等同 2.2 与 2.3。

## 3. 捕获后必须四选一

处置动作只有四种, 每种都规定了必须留下的证据:

| 编号 | 处置方式 | 适用情形 | 必须留下的证据 | 判定要点 |
| --- | --- | --- | --- | --- |
| 3.1 | 重试 | 结果不确定的瞬时故障 | 每次尝试记录 `attempt` 与失败原因; 次数上限来自配置 | 上限硬编码即不合格 |
| 3.2 | 降级 | 有可用兜底, 业务可继续 | WARNING 级日志与降级标记字段; 返回值标注数据来源 | 降级后不记录即不合格 |
| 3.3 | 转换并上抛 | 本层无处置能力 | 新异常携带原始原因链, 见第 4 条 | 丢弃原始异常即不合格 |
| 3.4 | 记录后标记失败 | 任务单元失败但不拖垮整体 | ERROR 级日志, 返回明确失败态, 汇总计入失败数 | 返回成功即不合格 |

判据:

- 每个捕获块必须能在代码中定位到 3.1 至 3.4 之一的证据; 一个块只允许一种主处置, 允许「降级加记录」这类组合, 但不得两种主处置并存导致语义含糊。
- 处置结果必须可被上层观察: 要么抛出, 要么返回带失败标记的结果对象, 要么写入汇总计数。

Python 正例(降级):

```python
try:
    cfg = remote_config.fetch()
except NetworkError as exc:
    logger.warning("远端配置不可用, 改用本地缓存", extra={"event": "config.fallback"})
    cfg = local_config.load()
```

Python 正例(记录后标记失败):

```python
try:
    result = checkin(account)
except CheckinError as exc:
    logger.error("账号签到失败", extra={"event": "checkin.failed", "account": account.id})
    return TaskResult(ok=False, account=account.id, reason=str(exc))
```

其他语言规则:

- Rust: 重试用显式循环加计数上限, 禁止 `loop` 无上限; 失败态用 `Result` 表达, 不得用 `Option` 抹平。
- C: 失败用错误码或错误结构体返回, 调用方必须检查; 降级必须在结构体里带来源标记。
- C++: 失败用异常或 `expected` 类结果返回; 降级必须在返回值里带来源字段。
- Go: 失败用 `error` 返回, 降级必须同时返回来源标记与 `error` 为 `nil` 的明确语义。
- Dart: 失败用异常或结果对象表达, 不得用 `null` 表示失败。
- TypeScript: 失败用抛出或结果联合类型表达, 不得用 `undefined` 表示失败。
- Shell: 失败用非零退出码, 降级必须打印来源并在汇总里标明。

## 4. 转换异常必须保留原因链

条款:

- 转换异常时, 新异常必须携带原始异常。上层据此可以定位真实原因, 而不是只看到一层包装。
- 原因链必须在日志的栈字段或专用字段中可见, 见 10_日志.md 的异常字段。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 4.1 | 上抛的新异常可回溯到原始异常类型与消息 | 回溯不到即不合格 |
| 4.2 | 无正当理由使用「切断原因链」的语法, 如 Python 的 `from None` | 不合格 |
| 4.3 | 日志或错误结构里只保留自定义文案, 不含原始异常信息 | 不合格 |

Python 正例:

```python
try:
    raw = json.loads(body)
except ValueError as exc:
    raise ParseError("响应不是合法 JSON") from exc   # 原始 ValueError 保留在 __cause__
```

Python 反例:

```python
try:
    raw = json.loads(body)
except ValueError:
    raise ParseError("响应不是合法 JSON")   # 原因链丢失, 无法判断是空响应还是格式错误
```

其他语言规则:

- Rust: 用 `map_err(|e| MyError::Parse { source: e })` 保留 `source`; 禁止 `map_err(|_| MyError::Parse)` 丢弃原始错误。
- C: 错误结构体带 `cause` 字段保存原始错误码与 `errno`; 不得在包装时把 `errno` 清零后只返回通用码。
- C++: 包装异常时用嵌套异常或 `std::exception_ptr` 保留原始异常; 禁止 `throw std::runtime_error("失败")` 丢弃原异常。
- Go: 用 `fmt.Errorf("解析响应失败: %w", err)`; 禁止 `%v` 或字符串拼接导致 `errors.Is` 失效。
- Dart: 抛新异常时带 `cause` 字段, 或用 `Error.throwWithStackTrace` 保留原栈。
- TypeScript: 用 `new ParseError("...", { cause: err })`, 保留 `cause` 属性。
- Shell: 包装失败信息时必须带原始命令与退出码, 例如 `exit 3` 与消息中的 `exit=3`。

## 5. 区分「取不到」与「出错」

条款:

- 取不到: 数据合法地不存在, 属于正常分支, 走兜底, 流程继续。
- 出错: 本应成功却失败, 属于异常分支, 走失败, 流程停止或标记失败。
- 两类情形不得由同一个分支、同一个返回值、同一个日志级别处理。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 5.1 | 缺失值必须有独立分支与兜底值 | 与异常合并处理即不合格 |
| 5.2 | 出错必须有失败标记, 不得返回空值冒充成功 | 返回空值即不合格 |
| 5.3 | 取不到用 WARNING, 出错用 ERROR | 级别错配即不合格 |

归类对照表:

| 情形 | 归类 | 处置 | 日志级别 |
| --- | --- | --- | --- |
| 键不存在、可选字段未配置、首次运行无历史记录 | 取不到 | 兜底默认值 | WARNING |
| 空文件、空目录、无匹配结果 | 取不到 | 空集合继续 | WARNING 或 INFO |
| 网络失败、超时、连接被重置 | 出错 | 重试或失败 | ERROR |
| 鉴权失败、权限不足 | 出错 | 不重试, 直接失败 | ERROR |
| 响应结构非法、字段类型不符、校验不通过 | 出错 | 失败 | ERROR |
| 磁盘不可写、编码错误 | 出错 | 失败 | ERROR |

Python 正例:

```python
value = cache.get(key)
if value is None:                 # 缓存未命中属于取不到, 走兜底
    logger.warning("缓存未命中, 使用默认配置", extra={"event": "cache.miss", "key": key})
    return default_config()
```

Python 反例:

```python
try:
    return cache.get(key) or remote_config.fetch()
except RemoteError:
    return None   # 取不到与出错混成一个 None, 上层无法区分
```

其他语言规则:

- Rust: 取不到用 `Option`, 出错用 `Result`; 禁止把 `Result` 直接 `ok()` 成 `Option` 后不记录。
- C: 取不到用独立返回码(如 1 表示无数据), 出错用另一个返回码(如 -1), 两者不得共用。
- C++: 取不到用 `std::optional`, 出错用异常或错误码, 接口注释写明两者语义。
- Go: 取不到用 `nil, nil`, 出错用 `nil, err`, 调用方必须分别处理。
- Dart: 取不到用可空类型, 出错用异常, 不得用同一可空值表示两种含义。
- TypeScript: 取不到用 `undefined`, 出错用抛出或结果联合类型, 不得共用 `undefined`。
- Shell: 取不到用专门的空结果出口(退出码 0 且输出为空), 出错用非零退出码。

## 6. 重试边界

条款:

- 只对结果不确定的故障重试: 超时、连接重置、连接被拒绝、限流类 429(业务允许时)、网关类 502 与 503 与 504。
- 明确失败不重试: 400 与 401 与 403 与 404 与 422 等 4xx、鉴权失败、参数错误、签名错误、业务明确拒绝。
- 重试次数、退避间隔、总时长上限必须来自配置, 不得硬编码; 配置缺省时必须存在上限。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 6.1 | 存在可重试与不可重试的分类判断, 且依据状态码或错误类型 | 所有错误一律重试即不合格 |
| 6.2 | 重试次数上限与退避参数来自配置项 | 字面量硬编码即不合格 |
| 6.3 | 存在总时长或总次数上限, 不会无限重试 | 无上限即不合格 |
| 6.4 | 每次重试记录 `attempt` 与失败原因 | 缺记录即不合格 |

Python 正例:

```python
for attempt in range(1, settings.max_attempts + 1):
    try:
        return client.post(url, timeout=settings.timeout_s)
    except (TimeoutError, ConnectionResetError) as exc:
        if attempt == settings.max_attempts:
            raise UpstreamUnavailable("重试次数用尽") from exc
        sleep(settings.backoff_s * attempt)   # 退避来自配置, 非硬编码
```

Python 反例:

```python
for _ in range(3):              # 6.2: 次数硬编码
    try:
        return client.post(url, timeout=10)
    except Exception:           # 6.1: 4xx 也会被重试
        sleep(1)
```

其他语言规则:

- Rust: 重试封装为带配置参数的函数, `for attempt in 1..=cfg.max_attempts`; 禁止 `retry` 宏式无上限循环。
- C: 重试计数变量必须来自配置读取结果, 并在总耗时超限时退出。
- C++: 同上, 重试策略封装为独立类型, 参数从配置注入。
- Go: 用 `for attempt := 1; attempt <= cfg.MaxAttempts; attempt++`, 配合 `context` 超时控制总时长。
- Dart: 重试逻辑集中一处, 参数从配置对象读取; 禁止在 UI 层与网络层各自实现一套。
- TypeScript: 重试封装为统一函数, 参数来自配置; 禁止依赖第三方库默认无限重试。
- Shell: 重试用显式计数变量, 且必须判断退出码类别, 不得对任何失败都循环重试。

## 7. 敏感信息

条款:

- 异常消息、异常栈、错误结构、日志中不得出现: 凭据原文、token、cookie、密码、完整响应体、完整请求头。
- 允许出现的内容: 字段名、长度、状态码、错误码、首尾各四位加中间掩码(掩码规则见 10_日志.md 第 8 条)。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 7.1 | 异常文本中不含 `token=`、`password=`、`authorization`、`set-cookie` 等键的取值 | 命中即不合格 |
| 7.2 | 异常文本中不含完整响应体或完整请求头 | 命中即不合格 |
| 7.3 | 日志扫描规则对上述模式零命中 | 门禁命中即不合格 |

Python 反例:

```python
raise ValueError(f"登录失败: {resp.text}")                  # 完整响应体与可能的 token 落盘
raise AuthError(f"token={token} 无效")                      # 凭据原文进入消息与栈
```

Python 正例:

```python
raise AuthError(f"鉴权失败, status=401, body_size={len(resp.content)}")   # 只保留可判定信息
```

其他语言规则:

- Rust: 错误类型实现 `Debug` 时必须避免打印凭据字段, 或对该字段打码。
- C: 错误结构体中不得保存凭据原文, 只保存状态码与错误码。
- C++: 异常 `what()` 返回值不得拼接凭据与完整响应体。
- Go: `fmt.Errorf` 中不得拼接 `resp.Body` 原文或请求头原文。
- Dart: 异常消息不得包含 token 与完整响应体。
- TypeScript: 抛出的 `Error.message` 与附带上下文不得包含凭据。
- Shell: `set -x` 输出与错误消息不得暴露带凭据的命令行参数。

## 8. 用户可见失败文案保持原样

条款:

- 重构、迁移、优化、拆分模块不得改动最终呈现给用户的失败文案。
- 文案变更必须来自单独需求单, 并附旧文案与新文案的逐字对照。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 8.1 | 用户可见文案有基线文件, 差异与基线不一致 | 不合格 |
| 8.2 | 文案改动没有对应需求单编号 | 不合格 |
| 8.3 | 标点、空格、全角半角与原文不一致 | 视为改动, 不合格 |

Python 正例:

```python
raise AuthError("登录状态已失效, 请重新登录")   # 与原文案逐字一致, 仅改内部实现
```

Python 反例:

```python
raise AuthError("登录失效")   # 重构时顺手改字, 用户可见面变化
```

其他语言规则: 所有语言同口径, 用户可见文案一律走基线文件比对, 不允许以「更通顺」「更简短」为理由改动。

## 9. 三层捕获边界

条款:

| 层次 | 位置 | 职责 | 判据 |
| --- | --- | --- | --- |
| 9.1 入口兜底 | 程序入口、CLI 主函数、服务请求最外层 | 捕获未处理异常, 记录 ERROR 与栈, 以非零退出码结束 | 入口不得无捕获裸奔; 也不得捕获后以 0 退出 |
| 9.2 任务单元隔离 | 单账号、单任务、单文件、单批次循环 | 单元失败不影响其他单元, 汇总计入失败数 | 循环内捕获后必须记录并标记失败, 不得 continue 了事 |
| 9.3 IO 边界转换 | 网络、文件、数据库、子进程调用处 | 把底层异常转换为本项目错误类型, 保留原因链 | 转换点必须集中, 不得在上层反复判断底层异常类型 |

判据:

- 三层缺任一层即不合格; 只做入口兜底而没有单元隔离, 视为不合格。
- 任务单元隔离允许全捕获, 但必须满足 3.4 的全部证据要求。
- IO 边界转换后, 上层只处理本项目错误类型; 上层直接判断第三方异常类型即不合格。

Python 正例(入口兜底):

```python
def main() -> int:
    try:
        return run_all()
    except Exception as exc:   # 入口兜底: 记录完整栈后以非零码退出
        logger.error("运行失败", extra={"event": "run.failed"}, exc_info=True)
        return 1
```

其他语言规则:

- Rust: `main` 返回 `Result`, 或就地捕获后打印到 stderr 并 `exit(1)`; 禁止 `unwrap()` 直接 panic 作为兜底。
- C: `main` 内统一错误出口, 释放资源后返回非零码; 禁止 `abort()` 掩盖错误。
- C++: `main` 捕获 `std::exception` 与未知异常, 输出栈信息后返回非零码。
- Go: `main` 中记录 `err` 后 `os.Exit(1)`; 禁止 `log.Fatal` 之外的空返回。
- Dart: 顶层 `runZonedGuarded` 或入口捕获后上报并返回非零码。
- TypeScript: 进程入口统一 `process.on("uncaughtException")` 与 `unhandledRejection` 处理, 记录后以非零码退出。
- Shell: `trap` 处理 `ERR` 与 `EXIT`, 输出失败命令与退出码; 不得只写 `set -e` 而无日志。
