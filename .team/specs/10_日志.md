# 10 日志规范

## 适用范围与效力

- 适用范围: 全语言。所有运行期输出的结构化日志, 包括服务、CLI、脚本、定时任务与 CI 内联脚本, 一律适用。
- 覆盖对象: 应用日志、任务日志、诊断日志。用户可见的终端交互输出与结果文件不属于日志, 但两者口径必须一致, 见第 9 条。
- 效力: 违反本文件任一条即判交付不合格, 退回重做, 不计入完成。退回意见必须写明条款编号与代码位置。
- 与语言细则的关系: 语言细则可补充各语言日志库的写法, 不得放宽本文的字段、级别与脱敏判据。
- 判定方式: 判据以「取一行日志做 JSON 解析与字段校验」的方式执行, 可脚本化, 不依赖人工通读。

## 1. 格式

条款:

- 一行一个 JSON 对象, 即 JSON Lines。禁止多行缩进的 pretty-print, 禁止一条日志跨行。
- 编码 UTF-8, 不带 BOM。
- 文件按运行落盘, 路径为 `logs/<run_id>.jsonl`。`run_id` 与日志字段中的 `run_id` 必须相同。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 1.1 | 逐行 `json.loads` 全部成功 | 任一行失败即不合格 |
| 1.2 | 每个文件行数等于 JSON 对象个数 | 存在续行或段落即不合格 |
| 1.3 | 文件名与字段 `run_id` 一致 | 不一致即不合格 |
| 1.4 | 文件为 UTF-8 且首字节不是 BOM | 带 BOM 即不合格 |

Python 正例:

```python
line = json.dumps(record, ensure_ascii=False, separators=(",", ":"))
handle.write(line + "\n")   # 单行写入, 不缩进
```

Python 反例:

```python
json.dump(record, handle, ensure_ascii=False, indent=2)   # 多行 pretty-print, 违反 1.1
```

其他语言规则: 统一使用各语言的标准 JSON 序列化器输出单行, 禁止手工拼接未转义字符串; 禁止把异常栈以原始多行文本直接写入 `msg`。

## 2. 基础字段

基础字段恒出现, 缺值写 `null`, 不得省略字段本身:

| 字段 | 类型 | 含义 | 判据 |
| --- | --- | --- | --- |
| `ts` | 字符串 | 事件时间, ISO 8601 带时区 | 必须能被解析为带偏移的时间, 如 `2026-11-08T09:31:02+08:00` |
| `level` | 字符串 | 级别, 取值 INFO 与 DEBUG 与 WARNING 与 ERROR | 其他取值即不合格 |
| `logger` | 字符串 | 产生日志的模块名, 与代码目录一致 | 空值或与目录不符即不合格 |
| `event` | 字符串 | 事件名, 稳定的点分标识, 如 `account.checkin.start` | 空值或含变量即不合格 |
| `msg` | 字符串 | 人类可读描述, 可用中文 | 空值即不合格, 但不得承载结构化数据 |
| `run_id` | 字符串 | 本次运行标识 | 与文件名不一致或缺失即不合格 |

判据:

- 对任一行的六个基础字段做存在性检查, 缺字段判不合格; 值为 `null` 允许, 字段缺失不允许。
- `ts` 不带时区判不合格; 使用本地朴素时间判不合格。
- `event` 必须是固定字符串枚举, 不允许把账号名、URL、错误消息拼进 `event`。

Python 正例:

```python
record = {
    "ts": datetime.now(timezone.utc).astimezone().isoformat(timespec="seconds"),
    "level": "INFO",
    "logger": "platform.runba",
    "event": "account.checkin.start",
    "msg": "开始签到",
    "run_id": run_id,
    "account": account_id,
}
```

Python 反例:

```python
record = {"level": "INFO", "msg": f"开始签到 {account_id} " + str(now)}   # 缺 ts/event/run_id, 信息拼进 msg
```

其他语言规则: Rust 用 `serde_json` 序列化结构体, 字段用 `Option` 并序列化为 `null`; Go 用结构体加 `encoding/json`, 空值用指针或 `any` 显式置 `nil`; TypeScript 构造对象后统一序列化, 禁止模板字符串拼 JSON; Shell 用 `jq -nc` 构造对象, 禁止 `echo` 手工拼接。

## 3. 上下文可选字段

按需出现, 出现时不得为空字符串, 无值则不写该字段:

| 字段 | 类型 | 含义 | 使用场景 |
| --- | --- | --- | --- |
| `platform` | 字符串 | 平台或站点标识 | 多平台任务 |
| `account` | 字符串 | 账号标识, 用脱敏后的标识, 不用明文手机号 | 账号级操作 |
| `stage` | 字符串 | 流程阶段, 如 `login`、`checkin`、`report` | 多阶段流程 |
| `attempt` | 整数 | 第几次尝试, 从 1 起 | 重试相关日志 |
| `duration_ms` | 整数 | 本步骤耗时毫秒 | 开始与结束配对时, 落在结束事件上 |

判据: 可选字段类型必须与表一致; `attempt` 从 1 起计数; `duration_ms` 不得为负数, 不得用浮点秒数替代。

## 4. 异常专用字段

打印异常时使用固定三字段, 不得把栈塞进 `msg`:

| 字段 | 类型 | 含义 | 判据 |
| --- | --- | --- | --- |
| `exc_type` | 字符串 | 异常类型全名 | 空值即不合格 |
| `exc_msg` | 字符串 | 异常消息, 已脱敏 | 含凭据即不合格 |
| `stack` | 字符串 | 栈文本, 换行以 `\n` 转义在 JSON 内, 物理上仍是单行 | 出现物理多行即不合格 |

判据:

- 只要 `level` 为 ERROR 且由异常触发, 三个字段必须同时出现。
- `stack` 内容遵守第 7 条脱敏要求。
- 禁止只写「未知错误」而不带 `exc_type` 与 `stack`, 与 11_Debug.md 第 6 条同口径。

Python 正例:

```python
except CheckinError as exc:
    logger.error(
        "账号签到失败",
        extra={"event": "checkin.failed", "exc_type": type(exc).__name__, "exc_msg": str(exc), "stack": traceback.format_exc()},
    )
```

其他语言规则: Rust 用 `{:?}` 或错误链展开到 `stack`; Go 用 `debug.Stack()`; TypeScript 用 `err.stack`; 均须先脱敏再写入。

## 5. 字段命名

条款:

- 字段名一律英文 snake_case, 全小写, 单词间下划线, 不使用连字符、驼峰、中文。
- 字段值可用中文原样, 包括 `msg` 与业务描述。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 5.1 | 字段名匹配 `^[a-z][a-z0-9_]*$` | 不匹配即不合格 |
| 5.2 | 同一语义在全仓使用同一字段名 | 出现 `runId` 与 `run_id` 并存即不合格 |
| 5.3 | 新增字段必须登记到本文表格 | 未登记即不合格 |

## 6. 级别判据

| 级别 | 判据 | 典型事件 | 误用判定 |
| --- | --- | --- | --- |
| ERROR | 本轮失败且影响最终结果 | 任务失败、批次中断、结果文件无法写出 | 仅影响单个可忽略项却用 ERROR, 不合格 |
| WARNING | 降级、兜底、规则失效, 但流程继续 | 缓存未命中、远端配置回退、单条数据跳过 | 流程已失败仍用 WARNING, 不合格 |
| INFO | 关键节点: 开始、结束、阶段切换、汇总 | 运行开始、账号开始、批次结束、汇总输出 | 逐条明细用 INFO 导致刷屏, 不合格 |
| DEBUG | 排查细节, 默认关闭 | 请求参数摘要、中间计算结果 | 生产默认开启 DEBUG, 不合格 |

判据:

- 级别必须与「是否影响最终结果」一致, 不允许按作者心情选择。
- 同一事件在不同阶段出现不同级别, 视为口径不一致, 不合格。

## 7. 一条日志一个事件

条款:

- 一条日志只描述一个事件。禁止把多个事件拼进一条 `msg`。
- 禁止在循环内全量打印响应体。需要逐条可见时, 只打 `status_code`、`body_size`、`error_code` 与必要标识。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 7.1 | `msg` 中不出现多个以分隔符拼接的独立事件 | 出现即不合格 |
| 7.2 | 循环内日志的 `msg` 不含完整响应体或完整请求头 | 出现即不合格 |
| 7.3 | 单次运行同事件重复条数不超过业务实际发生次数 | 数量对不上即不合格 |

Python 反例:

```python
logger.info(f"请求成功: {resp.status_code}, 响应: {resp.text}")   # 循环内打全量响应体, 违反 7.2
logger.info(f"开始下载 {url}, 下载完成, 开始解析, 解析完成")        # 四个事件拼一条, 违反 7.1
```

Python 正例:

```python
logger.debug("请求完成", extra={"event": "http.request.done", "status_code": resp.status_code, "body_size": len(resp.content)})
```

## 8. 脱敏

条款:

- 密钥、token、cookie、密码只保留首尾各四位, 中间用 `***`。
- 长度不足以保留首尾各四位时, 整体替换为 `***`, 不保留任何字符。
- 完整凭据永不落盘, 包括 DEBUG 级别与 `stack` 字段。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 8.1 | 对日志全文做凭据模式扫描, 零命中 | 命中即不合格 |
| 8.2 | 掩码格式为前四位加 `***` 加后四位 | 格式不符即不合格 |
| 8.3 | DEBUG 级别与异常栈同样执行 8.1 | 例外即不合格 |

Python 正例:

```python
def mask(value: str) -> str:
    if len(value) < 8:
        return "***"
    return value[:4] + "***" + value[-4:]
```

Python 反例:

```python
logger.debug(f"token={token}")   # 完整凭据进入 DEBUG, 违反 8.1 与 8.3
```

其他语言规则: 提供与上面同语义的统一掩码函数, 各模块只调用它, 不得各自实现; 禁止用「只在生产关闭 DEBUG」来替代脱敏。

## 9. 日志与结果口径一致

条款:

- 日志判定成功, 结果文件必须显示成功; 日志判定失败, 结果文件必须显示失败。
- 不允许存在两套口径, 例如日志汇总显示全部成功而结果文件含失败项。
- 汇总日志的计数必须能与结果文件逐项对上。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 9.1 | 汇总日志的成功数、失败数、总数与结果文件一致 | 任一不符即不合格 |
| 9.2 | 结果文件的每条记录能在日志中找到对应结束事件 | 缺失即不合格 |
| 9.3 | 同一 `run_id` 下不存在互斥结论 | 存在即不合格 |

## 10. 人工检索方式

常用 jq 命令, 在 `logs/<run_id>.jsonl` 所在目录执行:

```bash
# 筛出全部 ERROR
jq -c 'select(.level == "ERROR")' logs/<run_id>.jsonl

# 按 run_id 过滤(文件混放或合并分析时)
jq -c 'select(.run_id == "20261108_093102_a1b2")' logs/*.jsonl

# 统计各 level 条数
jq -r '.level' logs/<run_id>.jsonl | sort | uniq -c | sort -nr

# 按事件名聚合失败次数
jq -r 'select(.level == "ERROR") | .event' logs/<run_id>.jsonl | sort | uniq -c | sort -nr
```

判据: 上述命令必须能直接运行并得到结果, 不允许因字段缺失或值域不规范而需要额外清洗。

## 11. 降级要求

条款:

- 日志写入失败不得影响主流程, 主流程必须继续执行。
- 写入失败必须在 stderr 输出一次明确提示, 说明日志路径与失败原因, 不得静默。
- 「一次」指每次运行最多提示一次, 不得每次写失败都刷屏。

判据:

| 编号 | 判据 | 判定 |
| --- | --- | --- |
| 11.1 | 日志目录不可写时主流程仍完成, 退出码反映业务结果 | 因日志失败中断业务即不合格 |
| 11.2 | stderr 出现含日志路径与原因的提示 | 无提示即不合格 |
| 11.3 | 同一运行中该提示不超过一条 | 刷屏即不合格 |

Python 正例:

```python
except OSError as exc:
    if not state.warned:   # 每次运行只提示一次
        print(f"日志写入失败: path={log_path} reason={exc}", file=sys.stderr)
        state.warned = True
```

## 12. 交付前自检清单

- [ ] 每行都能被 JSON 解析, 文件为 UTF-8 无 BOM, 文件名为 `logs/<run_id>.jsonl`
- [ ] 六个基础字段齐全, 缺值写成 `null`, `ts` 带时区
- [ ] `level` 取值合法, 级别与「是否影响最终结果」一致
- [ ] `event` 为固定标识, 未拼接变量; 一条日志只描述一个事件
- [ ] 异常日志同时含 `exc_type`、`exc_msg`、`stack`, 栈为 JSON 内单行
- [ ] 凭据类信息全部按首尾四位加 `***` 掩码, 全量扫描零命中
- [ ] 汇总计数与结果文件逐项一致, 无两套口径
- [ ] 日志目录不可写时主流程不受影响, stderr 仅提示一次
