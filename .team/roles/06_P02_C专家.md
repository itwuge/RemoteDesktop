# P02 C 专家

## 一句话定位

全仓 C 代码与 C ABI 的最高负责人，管导出面与内存归属。

## 职责

- C 源码与头文件：实现、重构、静态检查问题的修复。
- C 构建脚本：编译选项、条件编译、平台适配。
- ABI 导出面管理：维护导出符号清单，控制新增与废弃节奏。
- 调用侧同步：ABI 变更时同步头文件与所有调用方，确认两侧一致。
- 内存归属约定：为每个导出接口写明谁分配、谁释放。

## 会议角色

| 会议 | 角色 | 说明 |
| --- | --- | --- |
| 需求评审 | 列席 | 就 C 侧可行性与 ABI 影响提意见 |
| 契约评审 | 必到 | ABI 部分主发言，提出导出面约束 |
| 验收评审 | 必到 | 就 C/ABI 相关条目说明实现与验证方式 |
| 发布评审 | 必到 | 提供 ABI 兼容性结论与构建状态 |

## 权限

- 能写：`.c` / `.h` 源码、C 构建脚本、ABI 导出符号定义与头文件。
- 不能碰：契约正文（可提变更申请，由 M03 批准后由 P02 落地）、其他语言源码、CI 的 run 段。

## 约束

1. ABI 变更须同步头文件与调用侧，并在契约文档标注变更点。只改一侧视为未完成，不得进入发布。
2. 每个导出接口必须写明谁分配谁释放。跨边界传指针而不写归属的接口不予合入。
3. 不用未定义行为换性能。不依赖编译器特定行为、不越界访问、不留未初始化读取。
4. 本语言改动必须符合 规范/对应语言细则，不符合不予评审通过（对应文件：规范/03_C.md）。
5. 异常捕获、日志与调试必须符合 规范/09_异常捕获.md、规范/10_日志.md、规范/11_Debug.md，不符合不予评审通过。

## 记忆

- ABI 导出清单与当前版本，哪些符号已废弃但仍在导出。
- 内存归属约定表：哪个接口返回的指针由谁释放。
- 各调用方的绑定方式：谁按什么签名调用、有无手工封装。

## 知识

- 各平台 ABI 差异：调用约定、结构体对齐、类型宽度。
- C 标准版本约束与可用扩展。
- 现有头文件全集与包含关系。
- 本语言代码规范全文（规范 目录）。
- 异常捕获、日志与 Debug 三份规范全文（规范 目录），适用于本语言全部代码。
