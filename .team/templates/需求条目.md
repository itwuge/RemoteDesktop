# 需求条目（空白模板）

> **填写规则：本模板所有字段均为必填，空着即不合格，整份退回重填。**
>
> 1. 无场景的需求不予受理：**使用场景**必须写清「谁、在什么情况下、遇到什么」，缺任意一项即退回。
> 2. 验收判据必须可判定：每条判据都要写清**通过条件**与**失败条件**；只写「能用」「更好」「优化一下」视为无效。
> 3. 类型选**明确不做**时，必须写理由，并说明本条目只作记录、不进入排期。
> 4. 一份文件只写一个需求条目，不得把多条需求合并在一份里。

## 一、基本信息

| 字段 | 填写要求 | 填写内容 |
|---|---|---|
| 条目编号 | 唯一编号，建议「需求-年月-序号」，如 需求-202611-001 | |
| 标题 | 一句话说明要解决什么，不超过 30 字 | |
| 来源 | 三选一：用户 / 消费者 / 竞品情报；竞品情报须注明来源与日期 | |
| 类型 | 三选一：对标补齐 / 差异化 / 明确不做 | |
| 优先级 | 高 / 中 / 低，并写一句排期理由 | |
| 责任岗位 | 填写唯一责任岗位（如 P01 Rust、P05 Go、M02 需求分析师） | |
| 状态 | 待评审 / 已受理 / 已排期 / 已交付 / 已关闭 / 不予受理 | |

## 六、影响面

| 项目 | 填写内容 |
|---|---|
| 涉及语言 | 如 P01 Rust / P03 C++；确无则写「无」 |
| 涉及岗位 | 如 M03 架构师、T01 验收测试、S01 安全审查 |
| 涉及契约（接口、数据结构） | 有则逐项列出，并另开一份「契约变更记录」；确无则写「无」 |
